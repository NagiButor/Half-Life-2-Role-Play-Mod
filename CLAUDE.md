- Ядро: `game/shared/hl2rpm_crashdebug.{h,cpp}` — чистый Win32 без Source-заголовков (в vcxproj `PrecompiledHeader=NotUsing`; снимает `#define`-запреты `strncpy/_snprintf/fopen`). Собирается в client и server; буфер «крошек» общий через named shared memory `Local\hl2rpm_crashdbg_<pid>`.

- При краше (VEH, до 3 отчётов за сессию, пропускается если подключён отладчик; ловит в т.ч. `int 3` от `Error()`) пишет `hl2rpm\crashes\crash_<время>.dmp` + `.txt` и запускает `hl2rpm\crashtools\analyze_crash.bat` (x86 `cdb` из Windows Kits → `.analysis.txt`). Запасной вариант — `crashtools\run_under_debugger.bat` (игра под cdb, ловит second-chance).
- Для символов PostBuild client/server копирует `.pdb` в `hl2rpm\bin`.
- Добавлять крошки в подозрительный код: `#include "hl2rpm_crashdebug.h"` + `RPM_CRUMB( "fmt", ... )` (дёшево, потокобезопасно). Уже расставлены в пути попаданий: `FireBullets`, `ImpactTrace`, `UTIL_DecalTrace`, серверный `DispatchEffect`, `CBaseHLBludgeonWeapon::Swing/Hit/ImpactEffect`, клиентский `DispatchEffectToCallback` (FX begin/end), `Impact()`/декали, `PerformCustomEffects`, `PlayImpactSound`.
- **Краши при выходе, смене карты и `mat_reloadallmaterials`** (NULL в `filesystem_stdio+0x29313`, 0xC0000374) были следствием переполнения массивов констант shader API (см. «Константы пиксельных шейдеров» ниже) — исправлено 2026-10-01, выход теперь с кодом 0. Если похожий «случайный» краш в чужом модуле вернётся — искать порчу кучи.

Исходники `.fxc` лежат в `sp\src\materialsystem\stdshaders`. Компилятор: `sp\src\game\ShaderCompile235\bin\ShaderCompile.exe` (standalone, без perl/DXSDK). Штатные `buildshaders.bat`/`buildepisodicshaders.bat` не использовать — они собирают всё.

Или списком через `process_shaders.ps1 -File <список.txt> -Version 30`.

- **Какой `.inc` видит C++:** в `game_shader_dx9_episodic.vcxproj` include-пути идут `fxctmp9;vshtmp9;include`, т.е. C++ берёт `.inc` из `fxctmp9\` (старый формат, классы `sdk_*`), а ShaderCompile235 пишет новые в `include\` (классы `SDK_*`). Если комбо шейдера меняются — обновить и `fxctmp9\<name>.inc` (копия из `include\` с заменой `SDK_`→`sdk_` в именах), иначе `.vcs` и C++ разойдутся → «Using invalid shader combo» → `Error()` → краш (так падали декали от пуль, 2026-09).
- **Проверка рассинхрона:** `python materialsystem\stdshaders\check_shader_combos.py` — сверяет каждый `.vcs` в `hl2rpm\shaders\fxc` с `.inc`, против которого собран C++ (число и порядок комбо). Запускать после любой компиляции шейдеров; должно быть `0 mismatched`.
- Новый fxc не принимает `register( D3DVERTEXTEXTURESAMPLER0, s0 )` (X3089) — писать `register( s0 )`.
- Hammer++ держит `hl2rpm\bin\game_shader_dx9.dll` открытой → PostBuild падает и удаляет собранную DLL. Либо закрыть Hammer, либо переименовать занятую DLL (`*.old_inuse`) и пересобрать.

- При изменении комбо/констант в `.fxc` сначала обновить `.inc`, затем пересобрать `game_shader_dx9_episodic` (C++ использует `.inc`; ошибки вида `vsh_forgot_to_set_dynamic_X` / необъявленные `iShadowMode` означают рассинхрон `.cpp` и `.inc`).

## Архитектура: deferred-рендер

Поверх Mapbase встроен deferred-рендер (порт Biohazard90 deferred / vs2022-deferred) с каскадными тенями солнца. Подробный разбор шейдеров — `E:\SourceModding\HL2RPMSOURCE\SHADER_RESEARCH_SUMMARY.md`.

- **Клиент** `sp\src\game\client\deferred\`: `viewrender_deferred.cpp` (порядок проходов: G-buffer → тени → освещение → композит), `cdeferred_manager_client.cpp` (инициализация/шейдерный API), `deferred_rt.cpp` (рендер‑таргеты), `cascade_t.cpp` (параметры CSM-каскадов), `clight_manager.cpp`/`def_light_t.cpp` (точечные/прожекторные/глобальный свет), `clight_editor.cpp` (редактор света), `flashlighteffect_deferred.cpp`.
- **Шейдеры** `sp\src\materialsystem\stdshaders\`: C++ проходы `defpass_gbuffer/shadow/composite.cpp`, обёртки материалов `deferred_brush/model/eyes/teeth.cpp`, проходы освещения `lighting_global/world/volume.cpp`, радиосити `radiosity_*.cpp`; общие HLSL-заголовки `common_deferred_fxc.h`, `common_shadowmapping_fxc.h`; общие константы C++/HLSL — `deferred_global_common.h` (CSM, режимы теней, метод фильтрации).
- Связь клиент ↔ шейдерная DLL идёт через интерфейс `IDeferredExt` (`IDeferredExt.cpp` в stdshaders, `IDeferredExtClient.cpp` в клиенте): клиент передаёт туда данные света/каскадов/погоды (`weatherData_t`), шейдеры читают их при биндинге констант. При изменении числа каскадов/регистров нужно синхронно править `deferred_global_common.h`, `cascade_t.*`, C++ биндинг констант и `.fxc` (регистры констант пиксельного шейдера ограничены — проверять пересечения `register(cN)`). Структуру `weatherData_t` менять только с пересборкой **обеих** DLL (client + game_shader_dx9).
- CSM: 2–4 каскада, подогнанных под фрустум камеры (practical split), текстел-снэппинг, дальние каскады обновляются реже (`r_csm_stagger`); пресеты — таблица в `cascade_t.cpp` (`r_csm_quality` 0..5, `r_csm_distance_scale`). Каждая перерисовка каскада ≈ полный проход сцены (~2 мс на открытой карте на GTX 960M) — на «Высоком» 2-й каскад обновляется раз в 2 кадра (движение/поворот камеры и сдвиг солнца всё равно форсируют обновление, `ShouldUpdateCascade`). Дальние каскады пропускают объекты с угловым размером < `r_csm_caster_cull` (0.006). Лямбда разбиения: 0.92 (Низкое–Среднее), 0.95 / 0.96 / 0.97 (Высокое / Очень высокое / Ультра; на Ультра первый каскад ~134 ед. с текселем 0.22 ед., второй ~460 ед. с 0.7) — при ~0.78 первый каскад тянулся на 420+ ед. и тени у ног были мыльными; `r_csm_split_lambda` (−1 = из пресета) — для подбора. Тенеобразователи каскадов берутся из **всех** листьев (`r_csm_novis 1` → `ViewSetupVis( true, … )`): по PVS камеры тени стен/пропов вне его мигали при переходе между листьями.
- **Теневые виды видят обе стороны стен**: мировые списки теневых видов строятся с `bShadowDepth` (`r_deferred_shadow_worldlists`) — обычный список отбрасывает грани, повёрнутые от камеры-«солнца», по стороне плоскости BSP (на `$nocull` не смотрит), и стена с nodraw-обратной стороной (vbsp не создаёт там грань) отбрасывала тень только краями; плюс `EnableCulling( false )` в `defpass_shadow.cpp`. Стоит ~+0.8 мс.
- **Тени солнца без `oDepth`**: теневой проход каскадов (и карты дождя) больше не пишет глубину из пиксельного шейдера — смещение даёт растеризатор (`SetShadowDepthBiasFactors( r_csm_slope_bias 0.5, r_csm_const_bias 0.5 текселя, не меньше 1.5 шага глубины )` в `COrthoShadowView::CommitData`, `EnablePolyOffset` всегда включён в `defpass_shadow.cpp`) → работает ранний Z (−20–25% кадра на открытых картах). Прежний наклон 3× отодвигал крутые грани за пол у их основания — светлая полоса у основания стен. **Глубина каскадов солнца 24-битная** (`NV_DST24`, `r_deferred_shadow_ortho_depth24`): движок на NVIDIA даёт теням 16 бит (в консоли `[deferred] shadow depth: hardware 16 bit, sun cascades 24 bit`), а шаг 16 бит на ~13 000 ед. к солнцу ≈ 0.2 ед. — как тексель первого каскада: акне на обращённых к солнцу поверхностях. Прожекторы/точки остаются на формате движка. Коэффициенты `SetShadowDepthBiasFactors` действуют на **все** материалы с `SHADER_POLYOFFSET_SHADOW_BIAS` до следующей установки — в основном виде этот вид смещения не использовать (глаза им «проваливались» за сцену).
- **Тени солнца** в `lightingpass_global_ps30.fxc` (`SunShadowPCSS` → `SunShadowCascade`), переписаны 2026-10-02 (A/B со старым шейдером: мутные пятна с полосами внутри полутени и прямоугольник акне на рифлёных воротах map_v11 ушли). **Фильтр — кубический B-сплайн** через аппаратные билинейные сравнения (каждое взвешивает пару текселей по оси): масштаб 1 (σ≈0.58 текселя) — 4 выборки, до 2 — 16; результат — гладкая функция положения, поэтому вблизи (тексель на много пикселей) нет «лесенок» углами и полос по столбцам текселей, как у прежнего диска Vogel. **Нормаль для теней — геометрическая** из буфера глубины: нормаль G-буфера с картой нормалей давала самозатенение по её узору (акне на рифлёном металле). `r_csm_shadow_normal 2` (по умолчанию): по каждой оси берётся сторона, чья линейная экстраполяция 1/z (на плоскости 1/z линейна в экране) предсказывает пиксель, — его собственная поверхность (8 выборок глубины, +0.3 мс); `1` — производные квадрата 2×2 (`ddx/ddy`: на складках смешивают обе поверхности, и разбиение на квадраты меняется при любом сдвиге камеры), `0` — нормаль G-буфера. Шаги экрана (`ddx` интерполянтов) берутся в начале `main`, до ветвлений. **Фильтр учитывает размер пикселя** (`r_csm_footprint` 0.5): масштаб B-сплайна ≥ 0.5 × (сколько текселей карты накрывает пиксель, по тем же шагам к соседям) — издали и под острым углом тени стержней/рёбер мельче пикселя перебирались от текселя к текселю при ходьбе (−30 % мерцающих пикселей, +0.2 мс). **Камера света каскада — в 12 000 ед. к солнцу** (`r_csm_center_origin 0`): вариант «в центре каскада с отрицательной ближней плоскостью» (`1`) отсекал тенеобразователи, стоящие от центра в сторону солнца (отсечение по пирамиде вида не учитывает отрицательную ближнюю плоскость): части теней висящих коробок test_deferred появлялись и пропадали от шага или поворота камеры (A/B по шагам 8 ед.). Снэппинг к текселю и шагу глубины — в double. Смещение — на стороне приёмника: вдоль нормали до `r_csm_bias_normal` (1.5) текселя (запас глубины ∝ tg угла, но у основания стены не пропускает свет) + наклонное `r_csm_bias_slope` (0.25) + 0.1 текселя; плоскость приёмника (dz на тексель, ±6 текселей). PCSS: поиск блокеров (16 взвешенных выборок R32F, `CommitTexture_CascadedDepthRaw`) → радиус полутени = расстояние × tg(0.2665°) × `r_csm_pcss_sunsize`, добавляется к B-сплайну как диск (масштаб = √(1+0.75·p²), ≤ 2); предел — `r_csm_pcss_penumbra` текселей (≤ 3) и одинаковая ширина в мировых единицах во всех каскадах (c71.z); дальние каскады без поиска. Нет блокеров, но аппаратная карта в центре говорит «тень» — фильтр (R32F теряет далёкие тенеобразователи на восходе). Переход каскадов — узкая полоса (smoothstep 0.92–0.995) с **тем же** фильтром следующего каскада (старая полоса 15 % с жёсткими 4 выборками двигалась с камерой — акне «то есть, то нет»). `r_csm_pcss 0` — тот же фильтр без поиска (масштаб 1); 2 — доля блокеров, 3 — сырая−приёмник, 4 — сырая глубина, 5 — сам множитель тени (с `r_deferred_debug_lighting_only 1` — белое альбедо — на экране только тень: так ищется её мерцание); 6 / 7 — видимость неба / SSAO, 8 — содержимое G-буфера (красный — 3D-скайбокс, зелёный — карта, синий — тело игрока). Отладка подгонки каскадов: `r_csm_debug_jitter <ед.>` (случайный сдвиг каждый кадр при неподвижной камере — тени не должны меняться), `r_csm_debug_log 1`. В теневых видах не пересчитываются затухание статических пропов и списки detail props (`UpdateRenderablesOpacity` считал их от камеры света и портил общее состояние); трава detail props попадает только в ближние каскады солнца своим путём (см. «Трава detail-спрайтов»). Внутри `[branch]` только `tex2Dlod( s, float4( uv, z, 0 ) )` (X3528). **Тело игрока в первом лице**: Mapbase обнуляет кости головы/рук только для основного вида, в карты теней идёт вся модель — голова и плечи затеняли видимые ноги/торс. Клиент выставляет `INT_RENDERPARM_DEFERRED_LOCAL_BODY` (слот 17, `public/renderparm.h`) на время отрисовки тела (`C_BasePlayer::DrawModel`), G-буфер пишет маркер 254, проход солнца для этих пикселей игнорирует тенеобразователи ближе `r_csm_body_bias` (36 ед.) — тень тела на земле остаётся, тень стены на теле тоже (если стена дальше). У стен с nodraw-обратной гранью у основания остаётся линия < 1 пикселя (за основанием в карте теней пусто, фильтр его захватывает).
- **Сглаживание** (`r_deferred_aa`: 0 нет / 1 FXAA / 2 TAA, по умолчанию TAA; пункт «Сглаживание» в меню «Графика»). MSAA движка в deferred-виде ничего не сглаживает (композит читает один свет на пиксель — края «лесенкой» и с 8x), а стоит дорого: кадр 18.3 мс вместо 16.2 (GTX 960M, 1600×900), и каждый полноэкранный проход/копия кадра платит за 8 сэмплов ещё раз. Поэтому `DeferredAA_DisableMSAA` (вызов в `CDeferredManagerClient::Init`) один раз за сессию выполняет `mat_antialias 0` — **без** `mat_savechanges`, реестр пользователя не меняется; `r_deferred_disable_msaa 0` оставляет MSAA. **FXAA 3.11** (`hl2rpm_fxaa_ps30`, `DrawDeferredFXAA`; `r_deferred_fxaa_subpix/_edge/_edge_min/_debug`) — ~0.8 мс, тонкие ветки и провода остаются пунктиром. **TAA** (`deferred/deferred_taa.cpp`, `hl2rpm_taa.cpp`, `hl2rpm_taa_ps30`) — ~1 мс:
  - джиттер проекции Halton(2,3)×8 через off-center вида (`DeferredTAA_JitterView` в начале `RenderView`: `CViewSetup::m_bOffCenter`, сдвиг ±0.5 пикселя) — движок сам строит такую проекцию для всех видов-копий (3D-скайбокс, вьюмодель, вода); `ProcessDeferredGlobals` при `m_bOffCenter` строит ту же матрицу (`MatrixBuildPerspectiveOffCenterX`), иначе лучи deferred-проходов и `GetMainViewToScreenTexBase()` разошлись бы с G-буфером;
  - репроекция по глубине G-буфера: скорость = разность **неджиттеренных** проекций точки в прошлом и текущем кадре (матрицы относительно текущей камеры + сдвиг камеры отдельно) — ошибка восстановления позиции сокращается, при неподвижной камере скорость ровно 0; небо (глубина 0) — направление; пиксели 3D-скайбокса верны сами (их глубина ×16);
  - история клиппится к боксу среднее ± `r_deferred_taa_clip` (1.25) σ окрестности 3×3 в YCoCg; вес истории `r_deferred_taa_history` (0.92) / `_history_min` (0.75, где история не сошлась), при быстром движении ×0.8; выборка истории Catmull-Rom (5 выборок), при нулевой скорости — одна;
  - **оружие и тело в первом лице** движутся с камерой: помечаются в трафарете битом 0x80 (`DeferredTAA_MarkCameraAttached` в композитном `DrawViewModels` и в `C_BasePlayer::DrawModel`) и берут историю из того же пикселя (материал с `$viewmodel 1`). Проходы TAA рисуются **прямо в кадр**: у рендер-таргетов с `MATERIAL_RT_DEPTH_SHARED` при MSAA заднего буфера свой буфер глубины-трафарета, меток там нет. История — две копии кадра в его формате (RGBA8), поэтому выход дизерится (иначе шаг 8 % «залипает»);
  - накопление джиттера — это бокс-фильтр размером в пиксель поверх фильтрации текстур: текстуры мылились. Композит (`composite_ps30`, c23.w) сэмплирует альбедо со сдвигом мипа `r_deferred_taa_mipbias` (−0.5); альфа-тест — без сдвига, как в G-буфере;
  - отладка `r_deferred_taa_debug` 1 движение / 2 насколько история подтянута / 3 маска оружия / 4 вес истории (красным поверх серого кадра, отдельным проходом — история не портится), `r_deferred_taa_info`, `r_deferred_taa_jitter 0`, `r_deferred_taa_stencil_test`. Движущиеся объекты без векторов движения (NPC, качающиеся ветки) держатся на клиппинге: шлейфов нет, сглаживание на них слабее. История сбрасывается на смене карты, прыжке камеры > `r_deferred_taa_reset_dist` (160) и потере содержимого RT.

Альбедо ищется только у **загруженных** материалов (`IsMaterialLoaded`): `FindMaterial` по имени пропатченной под кубмапу воды, которой в BSP нет, читал диск и падал с ошибкой — по нескольку мс на имя посреди кадра (кадры по 13 мс при ходьбе вдоль воды demo_map и «в 9 раз более дорогая» трассировка). В RGBA16F-атласы пробы заливаются крошечными квадами (без lock текстур). **На экране**: `deferred_gi_ps30` в половинном разрешении — ближняя сетка, где она кончается или ни одна проба не видит точку — дальняя, за ней — **оценка без проб** (открытая полусфера над поверхностью × видимость неба карты дождя из SSAO-таргета, который поэтому рисуется раньше GI; земля, освещённая солнцем); покрытие всегда 1, старый амбиент остаётся только пикселям неба/3D-скайбокса. Причины и что сделано:
  - `$fogcolor` (и прочие «forward»-цвета, `UpdateForwardMaterials`) **умножался на яркость мира повторно** при каждом пересканировании материалов: с `mat_queue_mode 2` `SetVecValue` применяется позже, и чтение переменной сразу после «возврата оригинала» давало уже масштабированный цвет, который становился «оригиналом» - после загрузки карты (погода ещё вплывает, масштаб 0.3-0.4) цвет воды уходил в чёрный. Теперь `GetGISkyLight` (`IDeferredExt.h`): по дню ×`r_deferred_gi_sky_open` (1.8) там, где видно всё небо, отклик видимости неба `v^r_deferred_gi_sky_gamma` (0.5; `SkyResponse` в `deferred_gi_ps30`, c10.w) — меньше неба в поле зрения получает относительно больше, и −30 % насыщенности (`_sky_desat`: точку освещает всё небо с бледным горизонтом, а не синий зенит). Слагаемые помещений — минимум без неба в поле зрения (`_min`) и отражённый внутри свет неба — сохраняют прежнее усиление `r_deferred_gi_sky_indoor` (4; множитель `GetGISkyIndoorFactor` на c4.w/c5.w): без этого глухая комната gi_test была вдвое темнее (A/B в одном запуске: теперь помещения 1.0–1.2 от прежнего, открытая тень — нейтрально-серая). Старый конвар скрыт и не сохраняется (в `config.cfg` пользователя он есть — без ошибки).
- **Консоль при старте/сохранении** (2026-10-17): `models/deferred/materialsphere_7..9` (шары редактора ламп) были на шейдере `editor_shader` из старого deferred-мода — «uses unknown shader» на каждой карте: теперь `DEFERRED_MODEL` (файлы мода). `cl_thirdperson` был `FCVAR_ARCHIVE | FCVAR_DEVELOPMENTONLY`: пишется в `config.cfg`, а при его исполнении невидим — «Unknown command» на каждом старте (флаг DEVELOPMENTONLY снят, `cam_thirdperson.cpp`). `CDeferredLight::TimegateThink` (лампы по времени суток) не было в datadesc: каждое сохранение — «Invalid function pointer in entity!», загрузка — «Failed to find function BADFUNCTIONPOINTER» (добавлен `DEFINE_THINKFUNC`; сообщение сохранения теперь называет класс и поле — `saverestore.cpp`).
- **LUX Shaders** (github LUX-Shaders-Team) — замена стоковых forward-шейдеров SDK2013 (LightmappedGeneric, VertexLitGeneric, вода, небо…), SM3.0; PBR, параллакса, листвы в нём нет; deferred-пайплайну мода брать оттуда нечего (идеи вроде `$EnvMapLightScale` у нас уже есть). Отметка: они тоже упирались в предел констант > c31 (у нас — `hl2rpm_psconstants.cpp`).
- **DXVK / другие графические API — проверено и отклонено** (2026-10-18). Движок рисует только через `shaderapidx9.dll` (закрыт, D3D9): родных DX10/11/12/Vulkan без исходников движка не сделать, возможны только переводчики вызовов D3D9 — DXVK (→ Vulkan) и D3D9On12 Microsoft (→ D3D12). `d3d9.dll` импортирует только `shaderapidx9.dll` (`Direct3DCreate9`, `D3DPERF_SetOptions`), а модули Source грузятся `LoadLibraryEx( …, LOAD_WITH_ALTERED_SEARCH_PATH )` (`tier1/interface.cpp`) — подмена должна лежать в `Source SDK Base 2013 Singleplayer\bin`, не рядом с `hl2.exe`. Замер DXVK 3.1.1 (x32; 2.7.1 ещё медленнее) на GTX 960M (драйвер 582.28, DXVK выбрал NVIDIA, «Binding model: Legacy»): картинка та же (те же шейдеры SM3), но в 1600×900 кадр **41–48 мс против 20–24** у D3D9, в 800×450 одинаково (~10.5 мс) — проигрыш на GPU, не на процессоре; `d3d9.floatEmulation = False` не помогает. Пользователь отказался — остаёмся на D3D9; к идее не возвращаться без его просьбы.
- **x64 / MP-база 2025 (ветка TF2) — проверено и отложено** (2026-10-23). Перенос мода на 64-битный SDK Valve 2025 г. (Source SDK Base 2013 Multiplayer, AppID 243750, `hl2_win64.exe`) отложен до официального x64 для одиночной игры: SDK Base SP (243730) и сам HL2 (220, после 20th Anniversary) — x86; 18.02.2025 Valve вынесла SP в ветку `singleplayer` репозитория без изменений с 2015 г.; x64-ветка Mapbase `mapbase-mp-2025` — только HL2DM/TF2. Для Steam x64 не нужен (Entropy: Zero 2 — Mapbase SP, x86, в Steam). Проверка стоковым episodic из x64 SDK (`E:\SourceModding\x64_spike`, итоги — `SPIKE_NOTES.md`): собирается без ошибок (VPC `/episodic`, платформа решения `win64`), но с `cl_localnetworkbackdoor 1` карта падает при подключении клиента (`engine.dll` зовёт `SendProxy` сервера с указателем −1); с `0` грузится, `save` работает, а после `load` у **всех** физических ограничений обнулены объекты (сами объекты восстанавливаются без сбоев — перепривязка указателей в закрытой `vphysics.dll` x64) → краш `CPhysHinge::Activate`; `changelevel2` работает, но возврат на посещённый уровень не находит его `.HL1` — уровень грузится заново. В самом SDK 64-битные поля сохранения не сходятся (`FIELD_EDICT` — 4 байта при 8-байтном `edict_t*`, `taskFailureCode` — intp при `FIELD_INTEGER`). Память на 32 битах не проблема: 7 загрузок тяжёлых карт (map_v11, demo_map_rus, map_v10, map_v11_001, сохранение/загрузка) — пик адресного пространства 1.85 ГБ из 4 (LAA), commit 1.25 ГБ, крупнейший свободный блок ≥ 2 ГБ (`x64_spike\logs\mem_run1.csv`, сэмплер `mem_sampler.ps1`). Слитый код TF2 2018 — справочник по **нашему** 32-битному движку, а не по x64-движку 2025 г. (см. «Слитые исходники движка»). Вернуться к теме, если Valve выпустит x64 SP/HL2, Mapbase — SP под x64, или память начнёт кончаться.

## Погода, небо, время суток

- **Скорость времени**: `sv_timecycle_speed_scale` (0.1, сервер) умножает `time_scale` всех карт: FGD-умолчание `time_scale 10` при `day_length_seconds 8640` давало сутки за 14.4 мин (солнце ползло на глазах), теперь 2.4 ч (×10 реального; подпись «× реального времени» в F1-редакторе стала верной). Замер: `sv_timecycle_set_speed 100` → ~33 игровые минуты за 20 с.
- **Сервер** `game/shared/weather/`: `env_weather` (целевой пресет, длительность перехода, авто-смена погоды — марковская цепь с весами по времени суток в `weather_shared.cpp`; создаётся автоматически на картах с `light_deferred_global`, в FGD — `deferred.fgd`). Там же таблица пресетов `WeatherParams_t` (9 обычных + `snow`, `ash` — в автосмене не участвуют, только вручную/из FGD — + `cumulus`, `stratocumulus`, `highclouds`; матрица переходов 14×14) и `Weather_SunlightColor()` (цвет солнца через атмосферу, те же коэффициенты, что в шейдерах неба). Консоль: `sv_weather <имя|номер> [сек]`, `sv_weather_auto 0/1`, `sv_weather_next`, `sv_weather_list`, `sv_weather_procedural_sky` (заменяет статичный skybox на `sky_proc_atmo_01`).
- **Клиент** `game/client/weather/`: `C_WeatherSystem` плавно смешивает параметры, считает влажность/лужи, молнии/гром, звук дождя/ветра, луну; `ModifyGlobalLight()` (из `CDeferredLightGlobal::GetState`) превращает погоду в свет/амбиент. `weather_render.cpp` — все проходы: облака (`weather_clouds_ps30`, raymarch в 1/2–1/4 разрешения с джиттером по IGN + золотое сечение по кадрам → `weather_cloudresolve_ps30`: текущий кадр сглаживается окном 3×3, история репроецируется по повороту камеры и клиппится по окрестности 3×3 — без шлейфов при движении; белый шум джиттера давал «песок» на кромках облаков), мокрые поверхности/лужи/высотный туман (`weather_post_ps30`; плёнка на шершавой поверхности — потемнение и слабое размытое отражение неба (≤15 % у горизонта), зеркалят только лужи — иначе «мокрость» сильно зависела от угла взгляда), GPU-струи дождя (`weather_rain_vs30/ps30`), лучи солнца (`volumpass_sun_ps30` + экранные god rays `weather_godrays_ps30` → буфер volumetrics), канал молнии (меш `hl2rpm/weather/lightning_bolt`). 3D-шум облаков и weather map генерируются на CPU (`weather_noise.cpp`).
- **Карта окклюзии дождя** (вид сверху, ortho): рендерится проходом теней с отдельным индексом `DEFERRED_SHADOW_INDEX_RAIN` (на индексе 0 она портила данные солнца) и без PVS (`render->ViewSetupVis( true, 1, … )` перед видом; `m_bForceNoVis` читает только `CViewRender::SetupVis`, теневые виды его не видят) — иначе PVS камеры отбрасывал крыши/пропы над игроком и пол под ними намокал. Брызги капель выше уровня глаз (`HL2RPM Precip Splash Position`) отбрасываются — иначе били «сквозь потолок» по крыше над игроком. Отладка: `r_weather_debug_view 1` (красный = открытое небо, синий = под крышей), `2` — сама карта. **Карта рисуется до передачи погодных констант кадра** (`RenderRainOcclusion` перед `WeatherRender_CommitFrame` в `viewrender_deferred.cpp`): наоборот кадр, перерисовавший карту (раз в секунду при ходьбе), читал новую карту через матрицу прошлой — видимость неба, мокрые поверхности и дождь на один кадр сдвигались на пройденное расстояние: **это и было «микромерцание как акне по всей поверхности, только при ходьбе»** (A/B записью ходьбы: 1400 «вспыхнувших» тайлов 8×8 = 17 % экрана в кадре перерисовки → 0; `r_deferred_rainmap_debug_late 1` возвращает старый порядок). Центр карты привязан к 4 текселям по xy и к 64 ед. по высоте (перерисовка того же мира даёт ту же карту).
- **Осадки** — свои системы частиц `particles/hl2rpm_weather.pcf` (`hl2rpm_rain`, `_rain_storm`, `_snow`, `_ash`; собираются из `rain_fx.pcf` скриптом `hl2rpm_extras/tools/make_weather_pcf.py` + `dmx.py`) и клиентские операторы в `weather/weather_precip.cpp`: `HL2RPM Precip Spawn` (диск вокруг камеры со сносом против ветра, свой RNG — таблица random particles.lib давала повторяющиеся точки), `HL2RPM Precip Cover` (карта крыш: тороидальная сетка 128×128 по 16u, проба на +1200 над камерой — вверх небо? вниз первая поверхность; видит world/func_detail/func_brush; под крышей не рождаются, время жизни = до удара), `HL2RPM Precip Splash Position` (брызги в реальных точках удара). Инициализатор particles.lib вызывается, только если пишет ещё не инициализированный атрибут → нужен `InitMultipleOverride() == true`; частицы обновляются в потоках (`r_threaded_particles`) → кэши под мьютексом. Яркость частиц и детальных спрайтов масштабируется по текущему свету. Convars `cl_weather_precip`, `_density`, `r_precip_cull(_debug)`.
- **Молнии**: классы близко/средне/далеко (звуки `sound/hl2rpm/weather/thunder/*`, задержка грома по расстоянию), канал из 2–5 импульсов, видимый разряд у горизонта. Вспышка применяется к глобальному свету **после** временного сглаживания (`r_deferred_light_global_smooth_tau`), иначе съедается. `cl_weather_lightning [0|1|2]` — вызвать удар (близко/средне/далеко; есть кнопка в F1-редакторе).
- Облака: второй октав детали и сильнее эрозия краёв; заполняющий свет неба ×0.75 (при 1.5 затенённые стороны были белыми); высококучевые — гряды (undulatus); при coverage > 0.93 «подложка» без дыр (пасмурно/туман). Отладка `r_weather_cloud_debug 1/2/3` (только солнце / только небо / непрозрачность) через `vecCloudParams3.w`. Ps_3_0 облаков на пределе регистров — деталь в световом марше не влезает. Форма облаков (3D-шум, период 8 км) сдвигается средним шумом карты погоды (`shapePos.xy += ( wm.ba − 0.5 ) × 0.6`): при малой облачности в каждом тайле стояли одни и те же облака — к горизонту они шли одинаковыми рядами. Параллакс: `r_weather_cloud_parallax`, скорость `r_weather_cloud_wind_scale`.
- Покрытие облаков **откалибровано по реальному шуму** (`CoverageThreshold` в `weather_clouds_ps30.fxc` и копия в `lightingpass_global_ps30.fxc` для теней облаков): coverage = доля закрытого неба. Меняя генерацию шума — перекалибровать (симуляция шума на numpy, подбор порога бисекцией).
- **Небо**: `procsky_atmo_ps20b.fxc` (компилировать `-ver 30` → `procsky_atmo_ps30.vcs`) + LUT атмосферы `sky_atmo_*_lutgen` (Hillaire). Параметризация sky-view LUT: u = sqrt(0.5−0.5·cos(азимут к солнцу)), v = sqrt(угол места) — генератор и выборка должны совпадать. LUT-ы билинейные (point sampling давал «ступеньки»). Небо освещается нетонированным солнцем (`weatherData_t::vecSkyLight`), цвет даёт сама атмосфера. Тонмап неба — расширенный Reinhard (W=5): вершины облаков белые, тени облаков серые. Диски солнца/луны за облаком × T³ (звёзды × T²). LUT перестраивается по **сглаженному** (переданному шейдерам) состоянию глобального света + 3 кадра «добивки»: по сырому после прыжка времени небо оставалось сумеречным. `r_deferred_skyatmo_lut_rebuild`, лог `[skylut]` при `cl_weather_debug 1`.

Полный редактор ламп — `r_deferred_light_editor_toggle`. `CLightEditorHelper::Update` (`vgui_editor_root.cpp`) не трогает окна, пока открыта консоль/меню (раньше закрывал их каждый кадр → команды из консоли «не работали»).

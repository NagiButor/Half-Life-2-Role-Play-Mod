## Отладчик крашей

- Ядро: `game/shared/hl2rpm_crashdebug.{h,cpp}` — чистый Win32 без Source-заголовков (в vcxproj `PrecompiledHeader=NotUsing`; снимает `#define`-запреты `strncpy/_snprintf/fopen`). Собирается в client и server; буфер «крошек» общий через named shared memory `Local\hl2rpm_crashdbg_<pid>`.
- Клиентская обвязка: `game/client/hl2rpm_crashhandler_client.cpp` (установка в `CHLClient::Init` сразу после получения `engine`, снятие последним в `CHLClient::Shutdown`; перехват spew для консоли; команды `rpm_crash_crumbs`, `rpm_crash_report`, `rpm_crash_test null|div|stack` (cheat), convar `rpm_crash_handler`).
- Если отчёта нет: Windows (WER) хранит полные дампы `hl2.exe` в `%LOCALAPPDATA%\CrashDumps`, а журнал «Application Error» даёт модуль/код/смещение. `0x80000003` в `tier0.dll` = `Error()`/Assert движка — текст ошибки читать из дампа (`da` по первому аргументу `tier0!Error`) или в «Last console output» отчёта.
- При краше (VEH, до 3 отчётов за сессию, пропускается если подключён отладчик; ловит в т.ч. `int 3` от `Error()`) пишет `hl2rpm\crashes\crash_<время>.dmp` + `.txt` и запускает `hl2rpm\crashtools\analyze_crash.bat` (x86 `cdb` из Windows Kits → `.analysis.txt`). Запасной вариант — `crashtools\run_under_debugger.bat` (игра под cdb, ловит second-chance).
- Для символов PostBuild client/server копирует `.pdb` в `hl2rpm\bin`.
- Добавлять крошки в подозрительный код: `#include "hl2rpm_crashdebug.h"` + `RPM_CRUMB( "fmt", ... )` (дёшево, потокобезопасно). Уже расставлены в пути попаданий: `FireBullets`, `ImpactTrace`, `UTIL_DecalTrace`, серверный `DispatchEffect`, `CBaseHLBludgeonWeapon::Swing/Hit/ImpactEffect`, клиентский `DispatchEffectToCallback` (FX begin/end), `Impact()`/декали, `PerformCustomEffects`, `PlayImpactSound`.
- **Краши при выходе, смене карты и `mat_reloadallmaterials`** (NULL в `filesystem_stdio+0x29313`, 0xC0000374) были следствием переполнения массивов констант shader API (см. «Константы пиксельных шейдеров» ниже) — исправлено 2026-10-01, выход теперь с кодом 0. Если похожий «случайный» краш в чужом модуле вернётся — искать порчу кучи.
- **Поиск порчи памяти — аппаратная точка на запись в cdb** (так найден виновник за один запуск): игра под cdb (`-cf init.txt`, **без** `-g`, иначе скрипт выполнится только при первом исключении), точка в уже загруженном модуле (`bu client!Функция`) ставит `bp модуль+смещение` (до загрузки модуля `bu модуль+смещение` не разрешается), а та — `ba w4 <адрес>` с командой `kb 60; gc`. В строках команд cdb пути к скриптам писать через `/` (обратный слэш съедается как escape), вложенные команды выносить в файлы `$$>< путь`. С `+mat_queue_mode 0` всё рисуется в основном потоке (детерминированно).

## FGD / Hammer

- Hammer++ грузит FGD по порядку: `commentary.fgd`, `deferred.fgd`, `halflife2_vizzys.fgd` (включает `base_vizzys.fgd`), `hl2rpm.fgd`, `hammerplusplus_fgd.fgd`. `commentary`/`deferred` делают `@include "base.fgd"`, который находится не рядом, а в `bin` Hammer'а (fallback по cwd).
- `hl2rpm.fgd` опирается на базовые классы из `halflife2_vizzys.fgd` (`Weapon`, `BaseNPC` и др.). Синтаксическая ошибка в любом раньше загружаемом FGD обрывает его разбор → каскад ошибок «undefined base class» и энтити «obsolete» в Hammer.
- Перед правкой FGD делать копию `*.fgd.bak_YYYYMMDD_...` (так принято в папке). Кастомные правки помечены комментарием `//Pravka`; правка свойств существующей энтити должна быть внутри её `[ ]`, а не отдельным блоком. Проверка синтаксиса: `python hl2rpm_extras/tools/fgdcheck.py <файл.fgd>`.
- У `light_deferred`/`light_deferred_spot` есть ключ `autoshadow` («Automatic shadow», 1 по умолчанию) — см. «Тени ламп».

## Архитектура: deferred-рендер

Поверх Mapbase встроен deferred-рендер (порт Biohazard90 deferred / vs2022-deferred) с каскадными тенями солнца. Подробный разбор шейдеров — `E:\SourceModding\HL2RPMSOURCE\SHADER_RESEARCH_SUMMARY.md`.

- **Клиент** `sp\src\game\client\deferred\`: `viewrender_deferred.cpp` (порядок проходов: G-buffer → тени → освещение → композит), `cdeferred_manager_client.cpp` (инициализация/шейдерный API), `deferred_rt.cpp` (рендер‑таргеты), `cascade_t.cpp` (параметры CSM-каскадов), `clight_manager.cpp`/`def_light_t.cpp` (точечные/прожекторные/глобальный свет), `clight_editor.cpp` (редактор света), `flashlighteffect_deferred.cpp`.
- **Шейдеры** `sp\src\materialsystem\stdshaders\`: C++ проходы `defpass_gbuffer/shadow/composite.cpp`, обёртки материалов `deferred_brush/model/eyes/teeth.cpp`, проходы освещения `lighting_global/world/volume.cpp`, радиосити `radiosity_*.cpp`; общие HLSL-заголовки `common_deferred_fxc.h`, `common_shadowmapping_fxc.h`; общие константы C++/HLSL — `deferred_global_common.h` (CSM, режимы теней, метод фильтрации).
- Связь клиент ↔ шейдерная DLL идёт через интерфейс `IDeferredExt` (`IDeferredExt.cpp` в stdshaders, `IDeferredExtClient.cpp` в клиенте): клиент передаёт туда данные света/каскадов/погоды (`weatherData_t`), шейдеры читают их при биндинге констант. При изменении числа каскадов/регистров нужно синхронно править `deferred_global_common.h`, `cascade_t.*`, C++ биндинг констант и `.fxc` (регистры констант пиксельного шейдера ограничены — проверять пересечения `register(cN)`). Структуру `weatherData_t` менять только с пересборкой **обеих** DLL (client + game_shader_dx9).
- CSM: 2–4 каскада, подогнанных под фрустум камеры (practical split), текстел-снэппинг, дальние каскады обновляются реже (`r_csm_stagger`); пресеты — таблица в `cascade_t.cpp` (`r_csm_quality` 0..5, `r_csm_distance_scale`). Каждая перерисовка каскада ≈ полный проход сцены (~2 мс на открытой карте на GTX 960M) — на «Высоком» 2-й каскад обновляется раз в 2 кадра (движение/поворот камеры и сдвиг солнца всё равно форсируют обновление, `ShouldUpdateCascade`). Дальние каскады пропускают объекты с угловым размером < `r_csm_caster_cull` (0.006). Лямбда разбиения: 0.92 (Низкое–Среднее), 0.95 / 0.96 / 0.97 (Высокое / Очень высокое / Ультра; на Ультра первый каскад ~134 ед. с текселем 0.22 ед., второй ~460 ед. с 0.7) — при ~0.78 первый каскад тянулся на 420+ ед. и тени у ног были мыльными; `r_csm_split_lambda` (−1 = из пресета) — для подбора. Тенеобразователи каскадов берутся из **всех** листьев (`r_csm_novis 1` → `ViewSetupVis( true, … )`): по PVS камеры тени стен/пропов вне его мигали при переходе между листьями.
- **Теневые виды видят обе стороны стен**: мировые списки теневых видов строятся с `bShadowDepth` (`r_deferred_shadow_worldlists`) — обычный список отбрасывает грани, повёрнутые от камеры-«солнца», по стороне плоскости BSP (на `$nocull` не смотрит), и стена с nodraw-обратной стороной (vbsp не создаёт там грань) отбрасывала тень только краями; плюс `EnableCulling( false )` в `defpass_shadow.cpp`. Стоит ~+0.8 мс.
- **Тени солнца без `oDepth`**: теневой проход каскадов (и карты дождя) больше не пишет глубину из пиксельного шейдера — смещение даёт растеризатор (`SetShadowDepthBiasFactors( r_csm_slope_bias 0.5, r_csm_const_bias 0.5 текселя, не меньше 1.5 шага глубины )` в `COrthoShadowView::CommitData`, `EnablePolyOffset` всегда включён в `defpass_shadow.cpp`) → работает ранний Z (−20–25% кадра на открытых картах). Прежний наклон 3× отодвигал крутые грани за пол у их основания — светлая полоса у основания стен. **Глубина каскадов солнца 24-битная** (`NV_DST24`, `r_deferred_shadow_ortho_depth24`): движок на NVIDIA даёт теням 16 бит (в консоли `[deferred] shadow depth: hardware 16 bit, sun cascades 24 bit`), а шаг 16 бит на ~13 000 ед. к солнцу ≈ 0.2 ед. — как тексель первого каскада: акне на обращённых к солнцу поверхностях. Прожекторы/точки остаются на формате движка. VS пишет растровую глубину (`vProjPos.z/w`): старая формула `dot(fwd)/zFar` расходилась с матрицей движка на ~2 текселя. **Прожекторы и грани куба точечных ламп тоже без `oDepth`** (`shadowpass_ps30`: глубину пишет только старый DPSM): смещение растеризатора `r_deferred_shadow_proj_slope_bias` (4) / `_depth_bias` (3e-6) задаётся в `CommitData` видов (`SetProjectedShadowDepthBias`) — картинка та же, а тень точечной лампы с гранями 2048² подешевела с ~9.5 до ~2–3 мс (demo_map_rus 57 → 77 FPS за счёт прожекторов). Коэффициенты `SetShadowDepthBiasFactors` действуют на **все** материалы с `SHADER_POLYOFFSET_SHADOW_BIAS` до следующей установки — в основном виде этот вид смещения не использовать (глаза им «проваливались» за сцену).
- **Тени солнца** в `lightingpass_global_ps30.fxc` (`SunShadowPCSS` → `SunShadowCascade`), переписаны 2026-10-02 (A/B со старым шейдером: мутные пятна с полосами внутри полутени и прямоугольник акне на рифлёных воротах map_v11 ушли). **Фильтр — кубический B-сплайн** через аппаратные билинейные сравнения (каждое взвешивает пару текселей по оси): масштаб 1 (σ≈0.58 текселя) — 4 выборки, до 2 — 16; результат — гладкая функция положения, поэтому вблизи (тексель на много пикселей) нет «лесенок» углами и полос по столбцам текселей, как у прежнего диска Vogel. **Нормаль для теней — геометрическая** из буфера глубины: нормаль G-буфера с картой нормалей давала самозатенение по её узору (акне на рифлёном металле). `r_csm_shadow_normal 2` (по умолчанию): по каждой оси берётся сторона, чья линейная экстраполяция 1/z (на плоскости 1/z линейна в экране) предсказывает пиксель, — его собственная поверхность (8 выборок глубины, +0.3 мс); `1` — производные квадрата 2×2 (`ddx/ddy`: на складках смешивают обе поверхности, и разбиение на квадраты меняется при любом сдвиге камеры), `0` — нормаль G-буфера. Шаги экрана (`ddx` интерполянтов) берутся в начале `main`, до ветвлений. **Фильтр учитывает размер пикселя** (`r_csm_footprint` 0.5): масштаб B-сплайна ≥ 0.5 × (сколько текселей карты накрывает пиксель, по тем же шагам к соседям) — издали и под острым углом тени стержней/рёбер мельче пикселя перебирались от текселя к текселю при ходьбе (−30 % мерцающих пикселей, +0.2 мс). **Камера света каскада — в 12 000 ед. к солнцу** (`r_csm_center_origin 0`): вариант «в центре каскада с отрицательной ближней плоскостью» (`1`) отсекал тенеобразователи, стоящие от центра в сторону солнца (отсечение по пирамиде вида не учитывает отрицательную ближнюю плоскость): части теней висящих коробок test_deferred появлялись и пропадали от шага или поворота камеры (A/B по шагам 8 ед.). История — две копии кадра в его формате (RGBA8), поэтому выход дизерится (иначе шаг 8 % «залипает»);

  - отладка `r_deferred_taa_debug` 1 движение / 2 насколько история подтянута / 3 маска оружия / 4 вес истории (красным поверх серого кадра, отдельным проходом — история не портится), `r_deferred_taa_info`, `r_deferred_taa_jitter 0`, `r_deferred_taa_stencil_test`. У моделей (VertexLitGeneric) масштабируется `$color2`: `$color` studiorender перезаписывает цветом сущности на каждой отрисовке — полупрозрачная оболочка Цитадели скайбокса светилась ночью. Растительность (`models/*` с foliage/grass/tree/... в имени, UnlitGeneric или полупрозрачная) при замене шейдеров становится `DEFERRED_MODEL` с alpha-test и half-lambert (`materialsystem_passthru.cpp`) — раньше светилась ночью; `$halflambert` и `$nofog` исходных материалов теперь сохраняются (флаги не копируются вместе с параметрами: материалы Цитадели — `$nofog`, и композит заливал её туманом скайбокса в плоский силуэт). Отладка: `r_deferred_list_materials <подстрока>` — материалы и их шейдеры. **Полупрозрачные материалы моделей** `DEFERRED_MODEL` по умолчанию отдаёт штатному VertexLitGeneric (`SHADER_FALLBACK`) — с освещением, «запечённым» в карту. Для прозрачной верхушки Цитадели (`props_combine/*citadel*`: `Combine_Citadel001b`, тросы) это давало голубоватую полосу днём и (с масштабом forward-материалов по времени суток) чёрную ночью; им ставится `$deferredtranslucent 1` — композит deferred-модели с прозрачностью, свет — из буфера света за ними (небо). Так же alpha-test получают полупрозрачные «волосяные» материалы моделей (`IsHairMaterial`: hair (не chair), eyelash, eyebrow, beard… — ресницы/пряди Аликс `hairbits`): полупрозрачный композит берёт свет непрозрачной поверхности **за** собой. **Трава detail-спрайтов** (`detail/detailsprites`, UnlitGeneric с цветом, «запечённым» на спрайт, — в тени стены была так же светла, как на солнце) становится `DEFERRED_BRUSH` с alpha-test (`r_deferred_detail_sprites`, применяется при загрузке карты), вершины спрайтов получают нормаль «вверх» (`detailobjectsystem.cpp`), а `CGBufferView` рисует их ещё и в G-буфер (`DrawDetailPropsInAllLeaves`) — композит прозрачного прохода освещает их по их собственным глубине и нормали: тень солнца, лампы, время суток (≈0.2 мс на поле травы demo_map). В тени не отбрасывают (теневых видов у detail props нет). Плавное исчезновение вдали (вершинная альфа) с alpha-test пропало — спрайты «выключаются» на `cl_detaildist`.

Теперь как в штатных шейдерах: `MORPHING && MORPHING_VTEX` → морф-текстура, иначе поток. Проверка: `r_flex 0` делает лица неподвижными — разницы с `r_flex 1` в покое быть не должно. - **SSAO и видимость неба**: `deferred/deferred_ssao.cpp` + `deferred_ssao_ps30`/`deferred_ssaoblur_ps30` (половинное разрешение, раздельный блюр с учётом глубины). Канал R — SSAO (шум поворота спирали **неподвижен** на экране: поворот каждый кадр без временного фильтра давал «кипение» в углах), канал G — «видимость неба». **Видимость неба** считается не пробами на пиксель, а картой `_rt_hl2rpm_skyvis` (128², 24 ед. на тексель, RGBA16F, `deferred_skyvis_ps30`), которая строится каждый раз при перерисовке карты дождя из её «сырой» глубины (цветовая цель карты дождя — R32F `_rt_hl2rpm_rainmap_raw`, её пишет теневой проход, как у атласа солнца): на тексель 192 пробы диска Vogel радиусом `r_deferred_skyvis_area` (128) с весами, плавно уходящими в 0 к краю; R — открытая доля диска для точки на своей вершине (самая низкая вершина тексела), G — для точки под навесом на уровне самой низкой земли вокруг (не ниже 512 ед. под вершиной; пустота за картой не считается), B — глубина вершины. Тап «закрыт», если его вершина выше уровня больше чем на `r_deferred_skyvis_cover` (24) ед. (мягко на 16); A — глубина того самого нижнего уровня. Вторая карта `_rt_hl2rpm_skyvis_wide` — то же с диском 512 ед. На пиксель: смещение 6 ед. по нормали, сравнение с вершиной своего столбца (сырая карта, point): «под навесом» — если вершина выше точки больше чем на 24 ед. (бордюры и ступени не в счёт). Снаружи — R × `r_deferred_skyvis_open_outdoor` (8: темнеют только почти замкнутые щели; у подножия каждой стены и бордюра была мягкая тёмная полоса — «вторая тень» в тени), выше вершины тексела (стены, кромки) — к 1. Под навесом — G × `r_deferred_skyvis_open` (2.5), причём 0, если точка ниже нижнего видимого уровня больше чем на 24 ед. (вокруг на её уровне земли не видно — глубоко внутри здания; раньше середина большого навеса судилась по его крыше и считалась открытой, а края у стен — закрытыми: инверсия и полоса в тени двора test_deferred под висящим блоком); для навесов выше 128 ед. — плавно карта 512 ед. (под высоким навесом небо видно через щели вокруг него). Старые 3 кольца × 8 бинарных проб давали ступени света параллельно каждой стене — «наложенные тени» в тени; ESM/экспоненциальное среднее высоты не годится — пустота за краем карты (глубина 1.0) «открывает» всё вокруг. `lightingpass_global_ps30` читает `.rg` (s6, c70) и гасит **только амбиент**: × SSAO × lerp(`r_deferred_skyvis_indoor`, 1, небо). Отладка: `r_csm_pcss 6` — видимость неба, `7` — SSAO (на белом альбедо `r_deferred_debug_lighting_only 1`; у бленд-материалов вторая текстура остаётся); с `r_csm_pcss 6` ещё `r_deferred_skyvis_debug 1/2/3` — открытая доля снаружи / под навесом / насколько точка «под навесом». Convars `r_deferred_ssao`, `_radius`, `_intensity`, `r_deferred_skyvis`, `_indoor` (клиент), `_area`, `_cover`, `_open`, `_open_outdoor`, `_debug` (шейдерная DLL); пункт SSAO есть в меню «Графика».

- **Туман**: композит меряет дистанцию тумана от камеры **текущего** вида (`GetWorldSpaceCameraPosition` в c3), а не от `IDeferredExt::GetOriginBase()` (основной вид): в 3D-скайбоксе (свои координаты, дистанции тумана /16) город был в ~16 000 ед. от камеры и тонул в тумане целиком — плоские силуэты. - **Лучи солнца в помещениях**: `volumpass_sun_ps30` — квадратичный шаг выборки (t = dist·u²) и «пыль под крышей» `r_weather_sunshafts_dust` (0.0015) по аппаратному сравнению с картой дождя (c65–c68); `r_weather_sunshafts_debug 1..5`.
- **Потеря содержимого рендер-таргетов** (сброс устройства, `mat_reloadallmaterials`, смена видеорежима): `InitDeferredRTs` в игре **не** вызывается (отложено до выхода из карты), текстуры возвращаются пустыми. Всё, что хранится в RT между кадрами, сбрасывается из `DeferredMaterials_OnRestore` (`materialsystem_passthru.cpp`): `DeferredGI_OnRTContentLost` (атлас проб заливается заново — иначе помещения становились светлыми и плоскими до смены карты), `DeferredTAA_Reset`, `DeferredPostFX_Reset`, `DeferredSkyLUT_ForceRebuild`. Новая система с такими RT должна добавить сюда свой сброс.
- **Ограничение (было до GI)**: в «сырые» R32F цветовые цели теневых видов (карта дождя raw, атлас солнца raw) мировая геометрия не попадает — только пропы и brush-энтити (мир рисуется depth-only путём движка). От этого страдают старая skyvis-карта и поиск блокеров PCSS для мировых тенеобразователей; аппаратные карты глубины полные.
- **Цена эффектов** (demo_map_rus, точка старта, GTX 960M, 1600×900, без MSAA): всё включено 17.6–18 мс (56 FPS), без GI/поста/контактных теней/AA — 13.7 мс; по отдельности ≈ пост 1.0, TAA 0.9, контактные тени 0.8, GI 0.3–1.5 (пока трассируется), SSR и SSAO < 0.5, пылинки и мягкие частицы ~0.1 мс.

## Погода, небо, время суток

- **Скорость времени**: `sv_timecycle_speed_scale` (0.1, сервер) умножает `time_scale` всех карт: FGD-умолчание `time_scale 10` при `day_length_seconds 8640` давало сутки за 14.4 мин (солнце ползло на глазах), теперь 2.4 ч (×10 реального; подпись «× реального времени» в F1-редакторе стала верной). Замер: `sv_timecycle_set_speed 100` → ~33 игровые минуты за 20 с.
- **Сервер** `game/shared/weather/`: `env_weather` (целевой пресет, длительность перехода, авто-смена погоды — марковская цепь с весами по времени суток в `weather_shared.cpp`; создаётся автоматически на картах с `light_deferred_global`, в FGD — `deferred.fgd`). Там же таблица пресетов `WeatherParams_t` (9 обычных + `snow`, `ash` — в автосмене не участвуют, только вручную/из FGD — + `cumulus`, `stratocumulus`, `highclouds`; матрица переходов 14×14) и `Weather_SunlightColor()` (цвет солнца через атмосферу, те же коэффициенты, что в шейдерах неба). Консоль: `sv_weather <имя|номер> [сек]`, `sv_weather_auto 0/1`, `sv_weather_next`, `sv_weather_list`, `sv_weather_procedural_sky` (заменяет статичный skybox на `sky_proc_atmo_01`).
- **Клиент** `game/client/weather/`: `C_WeatherSystem` плавно смешивает параметры, считает влажность/лужи, молнии/гром, звук дождя/ветра, луну; `ModifyGlobalLight()` (из `CDeferredLightGlobal::GetState`) превращает погоду в свет/амбиент. `weather_render.cpp` — все проходы: облака (`weather_clouds_ps30`, raymarch в 1/2–1/4 разрешения с джиттером по IGN + золотое сечение по кадрам → `weather_cloudresolve_ps30`: текущий кадр сглаживается окном 3×3, история репроецируется по повороту камеры и клиппится по окрестности 3×3 — без шлейфов при движении; белый шум джиттера давал «песок» на кромках облаков), мокрые поверхности/лужи/высотный туман (`weather_post_ps30`; плёнка на шершавой поверхности — потемнение и слабое размытое отражение неба (≤15 % у горизонта), зеркалят только лужи — иначе «мокрость» сильно зависела от угла взгляда), GPU-струи дождя (`weather_rain_vs30/ps30`), лучи солнца (`volumpass_sun_ps30` + экранные god rays `weather_godrays_ps30` → буфер volumetrics), канал молнии (меш `hl2rpm/weather/lightning_bolt`). 3D-шум облаков и weather map генерируются на CPU (`weather_noise.cpp`).
- **Карта окклюзии дождя** (вид сверху, ortho): рендерится проходом теней с отдельным индексом `DEFERRED_SHADOW_INDEX_RAIN` (на индексе 0 она портила данные солнца) и без PVS (`render->ViewSetupVis( true, 1, … )` перед видом; `m_bForceNoVis` читает только `CViewRender::SetupVis`, теневые виды его не видят) — иначе PVS камеры отбрасывал крыши/пропы над игроком и пол под ними намокал. Брызги капель выше уровня глаз (`HL2RPM Precip Splash Position`) отбрасываются — иначе били «сквозь потолок» по крыше над игроком. Отладка: `r_weather_debug_view 1` (красный = открытое небо, синий = под крышей), `2` — сама карта. **Карта рисуется до передачи погодных констант кадра** (`RenderRainOcclusion` перед `WeatherRender_CommitFrame` в `viewrender_deferred.cpp`): наоборот кадр, перерисовавший карту (раз в секунду при ходьбе), читал новую карту через матрицу прошлой — видимость неба, мокрые поверхности и дождь на один кадр сдвигались на пройденное расстояние: **это и было «микромерцание как акне по всей поверхности, только при ходьбе»** (A/B записью ходьбы: 1400 «вспыхнувших» тайлов 8×8 = 17 % экрана в кадре перерисовки → 0; `r_deferred_rainmap_debug_late 1` возвращает старый порядок). Центр карты привязан к 4 текселям по xy и к 64 ед. по высоте (перерисовка того же мира даёт ту же карту).
- **Осадки** — свои системы частиц `particles/hl2rpm_weather.pcf` (`hl2rpm_rain`, `_rain_storm`, `_snow`, `_ash`; собираются из `rain_fx.pcf` скриптом `hl2rpm_extras/tools/make_weather_pcf.py` + `dmx.py`) и клиентские операторы в `weather/weather_precip.cpp`: `HL2RPM Precip Spawn` (диск вокруг камеры со сносом против ветра, свой RNG — таблица random particles.lib давала повторяющиеся точки), `HL2RPM Precip Cover` (карта крыш: тороидальная сетка 128×128 по 16u, проба на +1200 над камерой — вверх небо? вниз первая поверхность; видит world/func_detail/func_brush; под крышей не рождаются, время жизни = до удара), `HL2RPM Precip Splash Position` (брызги в реальных точках удара). Инициализатор particles.lib вызывается, только если пишет ещё не инициализированный атрибут → нужен `InitMultipleOverride() == true`; частицы обновляются в потоках (`r_threaded_particles`) → кэши под мьютексом. Яркость частиц и детальных спрайтов масштабируется по текущему свету. Convars `cl_weather_precip`, `_density`, `r_precip_cull(_debug)`.
- **Молнии**: классы близко/средне/далеко (звуки `sound/hl2rpm/weather/thunder/*`, задержка грома по расстоянию), канал из 2–5 импульсов, видимый разряд у горизонта. Вспышка применяется к глобальному свету **после** временного сглаживания (`r_deferred_light_global_smooth_tau`), иначе съедается. `cl_weather_lightning [0|1|2]` — вызвать удар (близко/средне/далеко; есть кнопка в F1-редакторе).
- Облака: второй октав детали и сильнее эрозия краёв; заполняющий свет неба ×0.75 (при 1.5 затенённые стороны были белыми); высококучевые — гряды (undulatus); при coverage > 0.93 «подложка» без дыр (пасмурно/туман). Отладка `r_weather_cloud_debug 1/2/3` (только солнце / только небо / непрозрачность) через `vecCloudParams3.w`. Ps_3_0 облаков на пределе регистров — деталь в световом марше не влезает. Параллакс: `r_weather_cloud_parallax`, скорость `r_weather_cloud_wind_scale`.
- Покрытие облаков **откалибровано по реальному шуму** (`CoverageThreshold` в `weather_clouds_ps30.fxc` и копия в `lightingpass_global_ps30.fxc` для теней облаков): coverage = доля закрытого неба. Меняя генерацию шума — перекалибровать (симуляция шума на numpy, подбор порога бисекцией).
- **Небо**: `procsky_atmo_ps20b.fxc` (компилировать `-ver 30` → `procsky_atmo_ps30.vcs`) + LUT атмосферы `sky_atmo_*_lutgen` (Hillaire). Параметризация sky-view LUT: u = sqrt(0.5−0.5·cos(азимут к солнцу)), v = sqrt(угол места) — генератор и выборка должны совпадать. LUT-ы билинейные (point sampling давал «ступеньки»). Небо освещается нетонированным солнцем (`weatherData_t::vecSkyLight`), цвет даёт сама атмосфера. Тонмап неба — расширенный Reinhard (W=5): вершины облаков белые, тени облаков серые. Диски солнца/луны за облаком × T³ (звёзды × T²). LUT перестраивается по **сглаженному** (переданному шейдерам) состоянию глобального света + 3 кадра «добивки»: по сырому после прыжка времени небо оставалось сумеречным. `r_deferred_skyatmo_lut_rebuild`, лог `[skylut]` при `cl_weather_debug 1`.
- **F1-редактор** → «Время суток и погода» (`deferred/vgui/vgui_editor_timecycle.cpp`, команда `r_deferred_timecycle_editor`). Полный редактор ламп — `r_deferred_light_editor_toggle`. `CLightEditorHelper::Update` (`vgui_editor_root.cpp`) не трогает окна, пока открыта консоль/меню (раньше закрывал их каждый кадр → команды из консоли «не работали»).
- **Настройки → Графика / Эффекты**: `game/client/hl2rpm_options_graphics.cpp` встраивает две страницы в закрытый `OptionsDialog` GameUI (виртуальный `PropertyDialog::AddPage`, ABI vgui_controls совпадает с Valve); обе — один класс, заполняемый из таблицы (`GfxPageDesc_t`: convars, варианты, пресеты). «Графика» (11 пунктов): тени солнца/ламп, облака, лучи, дождь, мокрые поверхности, SSAO, мягкие тени, отражённый свет ламп, отражения в воде, сглаживание (`r_deferred_aa`). «Эффекты» (12 пунктов — больше на страницу не влезает, подсказка внизу уже не видна): GI, контактные тени, SSR, мягкие частицы, пылинки, пост-обработка, адаптация глаза, блум, цветокоррекция, эффекты объектива, глубина резкости, резкость. Диалог расширен на 150 px (вкладки не прокручиваются). `cl_options_graphics_page 0` отключает встраивание, `cl_options_graphics_select 1/2` открывает нужную страницу (для съёмки: `ui_clicks.ps1 -Extra "+cl_options_graphics_select 2" -Actions "wait:24","click:141,557","wait:4","shot"`). Новые токены — в `hl2rpm_extras/tools/add_loc_tokens.py`, после запуска убрать `*.bak_*` из `resource` мода и обновить копии в `hl2rpm_extras/resource`.

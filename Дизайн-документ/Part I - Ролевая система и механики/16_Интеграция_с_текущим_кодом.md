## 2. Что нужно добавить (по порядку)

### Этап 1 — «Ядро персонажа»
1. **Хранилище данных игрока**: характеристики, навыки, перки, черты, уровень, XP, ОС, Резонанс, Человечность, Влияние, ГС, Подозрение, репутации фракций, флаги. Должно **сохраняться** в сейве и **переживать смену карт** (`trigger_changelevel`). Варианты: поля в `CBasePlayer` с `DECLARE_DATADESC`, или отдельный `ISaveRestoreBlockHandler` по образцу `GetDialogSaveRestoreBlockHandler()`.
2. **Данные в файлах** (KeyValues, как уже принято):
   - `scripts/rpg/attributes.txt`, `skills.txt`, `perks.txt`, `traits.txt`, `implants.txt`;
   - `scripts/rpg/factions.txt` (ID, названия, стартовые значения, матрица отношений);
   - `scripts/rpg/items.txt` — расширить `inventory_weights.txt`: База, категория, контрабанда (кат.), состояние, требования, «заметность» для рамок КПП.
3. **Формулы** (файлы 02, 03, 05) — в одном модуле, чтобы правки баланса не трогали логику.
4. **Экран создания персонажа** и **экран уровня**.

### Этап 2 — «Мир реагирует»
5. **Многофракционная репутация**: заменить `int reputation` в `CQuestSystem::PlayerData` на словарь `faction → value`. Сохранить совместимость: старый `require_rep` = Лямбда (или «главная» фракция NPC).
6. **Расширение диалогов** (файл 09, раздел 7): условия `require_*`, проверки `check`/`fail_next`, эффекты `xp`, `rep`, `civil`, `credits`, `give_item`, `set_flag` и т.д.
7. **Глобальные флаги и «состояние мира»**: текущий акт, флаги событий (MQ, фракции), состояния секторов. Для карт — сущность-«переключатель» (или VScript), которая при загрузке карты включает нужный набор объектов и NPC для текущего акта (баррикады, патрули, руины).
8. **XP и уровни**: награда XP в `QuestDef` (сейчас только предметы), XP за убийства (у `quest_system` уже есть обработка событий убийства), за навыки.

### Этап 3 — «Закон»
9. **Подозрение и ГС**: зоны контроля (trigger-объёмы «зона Альянса», «запретная зона»), реакции ГО (проверка, досмотр, арест), «свидетели» — флаг у NPC и камеры/сканеры как источники улик.
10. **Отношения ИИ** — менять отношения классов NPC к игроку от ГС и Подозрения (в Mapbase есть удобные средства управления отношениями).
11. **Маскировка** — по экипированному костюму (`GetEquippedSuitClass`).

### Этап 4 — «Ремесло»
12. Мини-игры: отмычка, мультитул (4 вида), пароли терминалов.
13. Торговля (на основе окна лута).
14. Состояние предметов, ремонт, улучшения на фабрикаторах, крафт.

### Этап 5 — «Жизнь»
15. Расписания NPC (работа, дом, очереди), привязанные к `env_timecycle`.
16. Компаньоны (колесо команд, одобрение).
17. Работа-смены, жильё, обыски.
18. Сдвиг (замедление времени) и способности Резонанса.

## 3. Соглашения об именовании (чтобы дизайн-документ и данные совпадали)

| Сущность | Формат ID | Пример |
|---|---|---|
| Квест | `mqNN_slug`, `<фракция>NN_slug`, `sqNN_slug`, `cqNN_slug` | `mq02_papers`, `go01_volunteers`, `sq06_water` |
| Флаг | `<квест>_<событие>` или `world_<событие>` | `mq02_forged_id`, `world_stolga_shelled` |
| Фракция | латиницей из файла 06 | `lambda`, `shareholders`, `remnant` |
| NPC (имя сущности в карте) | `npc_<имя>` | `npc_kadar`, `npc_vera_lanskaya`, `npc_kwiatkowski` |
| Предмет | `item_<slug>` | `item_forged_id_card`, `item_multitool_mk2` |
| Локация (для журнала/карты) | ID из Part II | `C17-04`, `KZ-05` |

## 4. Риски и как их обойти

| Риск | Решение |
|---|---|
| Лимит `MAX_EDICTS` = 2048 одновременно живых сетевых сущностей | Население сектора — не больше ~120 NPC одновременно; «массовка» — через спавн-зоны рядом с игроком |
| Большие открытые сектора и производительность | Секторный мир (Part II, файл 01), областные порталы, 3D-скайбокс |
| Состояния мира по актам множат работу левел-дизайнеров | Одна карта + слои объектов по актам (включаемые группы), а не 4 копии карты |
| Переход между картами сбрасывает данные | Хранилище игрока из этапа 1 + глобальные флаги в сейве |
| Объём озвучки | Озвучка ключевых NPC; массовка — субтитры + переиспользование реплик HL2 (граждане, ГО, Надзор) |

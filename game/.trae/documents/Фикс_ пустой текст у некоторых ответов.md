## Почему часть текста пропадает
- В `CUtlVector` из Source SDK при сдвигах/расширениях используется `Q_memmove` (побайтовое перемещение объектов), см. [utlvector.h](file:///e:/SourceModding/HL2RPMSOURCE/source-sdk-2013-mapbase-v8.0/sp/src/public/tier1/utlvector.h#L502-L515).
- У нас `DSDialogOption` содержит `CUtlString`. Когда `options` растёт (`SetSize(...)`), элементы могут быть «побайтово перенесены», из‑за чего строки в уже добавленных опциях повреждаются. Симптом типичный: последний вариант виден, предыдущие становятся пустыми.

## План исправления (без изменения формата txt)

- Изменить `DSDialogNode::options` с `CUtlVector<DSDialogOption>` на `CUtlVector<DSDialogOption*>` (вектор указателей безопасно memmove’ится).
- В парсинге `options` всегда аллоцировать `new DSDialogOption` и складывать указатели по индексу.

## 2) Обновить все места использования options
- В `SendDialogNodeToPlayer`:
  - Итерироваться по `options` как по указателям.
  - Пропускать `NULL` (если вдруг дырка по индексу).
- В `DialogSystemServer::HandleDialogChoice`:
  - Брать `const DSDialogOption*` по `optionIndex`.

## 3) Корректное освобождение памяти
- При перезагрузке/удалении диалога:
  - Для каждой ноды удалить все `DSDialogOption*`, затем ноду.

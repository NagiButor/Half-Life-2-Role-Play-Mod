## Что видно по логу и что всё ещё ломается
- В логе есть момент, когда у выбранного элемента `armed=1`, `sup=1`, `red=0` (строка 186) — то есть по текущей телеметрии красная заливка на hover при actions **не должна** появляться.
- Ты при этом наблюдаешь обратное: **при видимых Take/Drop, если навести на основную строку — она всё равно подсвечивается**, а не должна.
- Параллельно лог показывает, что стрелки обрабатываются дважды (Pressed + Typed), из-за чего возможен двойной шаг.

## План исправления (без ввода консольных команд)
### 1) Жёстко запретить подсветку item-строк при видимых actions (по колонке)
В `CInvOptionButton::PaintBackground()` (для `m_nIndex >= 0`):
- Если в **этой же колонке** видны action-кнопки (`Take/Drop` справа или `Put/Drop` слева), то принудительно считать `suppressArmed=true` независимо от результата `AreActionsVisibleForItem`.
- Это убирает подсветку на hover/selected даже если вдруг `AreActionsVisibleForItem` на каких-то кадрах возвращает false.

Т.е. логика будет:
- `bool columnHasActions = (col==0 ? (left actions visible) : (right actions visible));`
- `if (columnHasActions) suppressArmed = true;`

### 2) Устранить двойной шаг клавиш
- В `OnKeyCodeTyped` **не форвардить стрелки** в `OnKeyCodePressed`.
- Оставить форвардинг только для `Enter/PadEnter` (если нужно), с дедупликацией относительно `OnKeyCodePressed`.

### 3) Проверка по следующему логу
- В момент, когда `Take/Drop` видны справа, при наведении мыши на строку справа не будет красной заливки (и `PAINTTICK ... red=0` сохранится).
- Одно нажатие стрелки будет менять индекс только на 1 (исчезнет паттерн Pressed→Typed→Pressed для одного нажатия).

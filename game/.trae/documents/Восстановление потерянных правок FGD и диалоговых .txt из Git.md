## Цель
- Восстановить ровно те правки в FGD и скриптовых диалоговых .txt, которые «пропали» после смены аккаунта, используя Git как источник истины, а .trae/documents — как чеклист ожидаемых изменений.

## План восстановления (после подтверждения)
### 1) Собрать “чеклист ожидаемых файлов” из .trae/documents
- Пройтись по документам, которые описывают изменения, и сформировать точный список целевых файлов:
  - FGD: base_vizzys.fgd, halflife2_vizzys.fgd, hl2rpm.fgd (и любые дополнительные .fgd, если в записях всплывут)
  - Диалоги: scripts/dialogs/*.txt (минимум test_npc_2.txt), плюс scripts/protagonists/*.txt если они тоже менялись
- Для каждого файла выписать “что должно быть восстановлено” (например: новые keyvalues, обновлённые подсказки health, новые энтити/классы).

### 2) Найти, где именно Git хранит эти правки
- Найти git-root(ы), в которых реально лежат эти файлы (возможны варианты: отдельные репозитории или один общий).
- Для каждого git-root:
  - поднять список изменений по истории/веткам/стешам/рефлогам
  - отфильтровать изменения только по целевым путям и маскам (*.fgd, scripts/**.txt)

### 3) Извлечь эталонные версии/патчи из Git
- Для каждого целевого файла определить “источник”:
  - конкретный коммит (если правки были закоммичены)
  - stash (если правки были застешены)
  - reflog/висячий коммит (если коммит был, но ветка/HEAD уехали)
- Сформировать набор операций вида: файл → взять содержимое из <источник> или применить diff.

### 4) Безопасно восстановить файлы в рабочем состоянии
- Сделать резервные копии текущих версий файлов перед восстановлением.
- Применить восстановление:
  - если файл должен совпасть с версией из Git → восстановить целиком
  - если правки частичные → применить патч с разрешением конфликтов

### 5) Проверить, что восстановилось именно то, что нужно
- Сверить итог по чеклисту из .trae/documents:
  - FGD: наличие новых keyvalues/классов, отсутствие синтаксических поломок
  - Диалоги .txt: корректная KeyValues-структура, присутствие нужных полей/веток
- Финально убедиться, что Git больше не показывает “пропавших” изменений (или показывает ровно то, что ожидается).

### 6) Отчёт
- Выдать список восстановленных файлов (пути) и источники (коммит/стеш/рефлог), плюс краткое описание восстановленного смысла (например: “добавлены keyvalues npc_approach/approach_distance/approach_run в trigger_dialog_start”).

## Примечание по рискам
- Если окажется, что нужные FGD/.txt сейчас лежат вне git-репозитория (как просто копии для игры/инструмента), восстановление сделаю из Git в “каноническом” месте и синхронизирую копии туда, где они реально используются (FGDs/Mapbase и hl2rpm/scripts).

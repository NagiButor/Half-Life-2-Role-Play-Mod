## Почему снова падает
- Текущий креш в `CUtlBinaryBlock::Length()` при `pOpt->text.Get()` означает, что **указатель `pOpt` невалидный** (или его память перезаписана) — это уже не про `NULL` строки, а про повреждение объекта.
- Даже с `AddToTail(NULL)` в парсере остаётся риск, что где-то в рантайме в `node->options[]` окажется мусорный адрес (особенно при разреженных индексах/перезагрузках/инкрементальных сборках).

## План решения (самый надёжный)
## 1) Убрать динамические указатели из options полностью
- Переписать `DSDialogOption` так, чтобы он был **POD (без CUtlString)**:
  - `char text[256]`, `int nextId`, `int flags`, `char serverSequenceName[128]`, `bool spoils`.
- В `DSDialogNode` сделать `CUtlVector<DSDialogOption> options;` (хранение по значению).

## 2) Обновить парсер ParseNodeKV/ParseOptionKV
- `ParseOptionKV` заполняет `char[]` через `Q_strncpy`.
- Для нумерованных опций (`"0"`, `"3"`) вместо `SetSize()` использовать:
  - `while (outNode.options.Count() <= optIndex) outNode.options.AddToTail(defaultOption);`
  - где `defaultOption` заранее обнулён.

## 3) Обновить SendDialogNodeToPlayer и обработчик выбора
- `SendDialogNodeToPlayer`: читать текст из `option.text` и не трогать `CUtlString::Get()` вообще.
- `DialogSystemServer::HandleDialogChoice`: доступ к `server_sequence` и `spoils` через поля POD.

## 4) Упростить освобождение памяти
- В `DeleteDialog`/`ParseNodeKV` убрать `delete` для options (они больше не на heap) — достаточно `RemoveAll()`.

## Проверка
- Диалог по `E` больше не должен падать (исключаем любые невалидные указатели в options).
- Разреженные индексы опций в .txt продолжают работать.
- Ранее фикс с отображением всех опций остаётся актуальным (теперь безопасно без указателей).

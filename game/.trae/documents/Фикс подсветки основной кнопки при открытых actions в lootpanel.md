## Проблема
- Сейчас в lootpanel, когда для предмета открыты action-кнопки (Put/Drop или Take/Drop), большая кнопка иногда снова начинает краснеть при наведении после ховера по маленьким кнопкам.
- По требованию: пока action-кнопки видимы внутри большой — большая никогда не должна краснеть; как только actions скрылись — большая снова может краснеть (hover/selected).

## Причина (по текущей реализации)
- В [vgui_lootpanel.cpp](file:///e:/SourceModding/HL2RPMSOURCE/source-sdk-2013-mapbase-v8.0/sp/src/game/client/vgui_lootpanel.cpp) в `CInvOptionButton::PaintBackground()` красная заливка допускается даже если кнопка остаётся `IsDepressed()` (или иным образом попадает в состояние заливки), а `suppressArmed` используется только для armed/selected.
- Из-за этого при появлении/анимации/перехвате мыши маленькими кнопками возможен сценарий, когда большая снова заливается.

## Правка
- В `CInvOptionButton::PaintBackground()` изменю правило заливки:
  - было: `depressed || (!suppressArmed && armed) || (!suppressArmed && selected)`
  - станет: `!suppressArmed && (depressed || armed || selected)`
- То есть `suppressArmed` будет блокировать красную заливку полностью (и для hover, и для selected, и для depressed) именно для той большой кнопки, у которой открыты actions.

## Проверка
- Быстрый компил-чек через диагностику IDE.
- В игре: открыть lootpanel, кликнуть по предмету, убедиться что:
  - при видимых actions большая кнопка не краснеет ни при каком ховере,
  - после скрытия actions (повторный клик по предмету/уход/клавиатура) большая снова краснеет на hover/selected.

# Deferred-рендер, часть 3: GI v3, POM, ветер, листва, occlusion culling, решения (DXVK, x64), финальные проходы графики

> Общая техническая справка для любой AI-модели. Правила — `../PROJECT.md`, статус — `../CURRENT_STATUS.md`. Новые знания по теме добавлять сюда; версии и измерения в датированных разделах сверять с текущим кодом.

- **GI переписан** (2026-10-11, `deferred/deferred_gi.cpp`; абзац «GI-пробы» выше описывает прежнюю версию - числа и названия конваров сверять с кодом). Ближняя сетка 32×32×10, 6 плоскостей атласа (видимость неба, непрямое солнце: яркость SH + цвет, свободные дистанции, отражённый свет неба: SH + цвет). Лучи - пачками по 32 с поворотом на пробу и проход (`r_deferred_gi_rays` 192, дальняя сетка 64): сначала грубо, потом уточнение. **Многократные отскоки** - «радиосити по пробам»: попадания лучей хранятся (`GIHit_t`, 20 байт), свет в них берётся из поля проб (`_multibounce`). Фильтр по соседям с учётом видимости (`_filter`) убрал «куски» света в комнатах. **Brush-энтити заслоняют свет** (`_brush_entities`): `func_brush`, двери и т.п. - через `ICollideable`-заглушки (`SOLID_BSP`, владелец - мир: сама энтити может быть удалена между сканами), неподвижные ≥ 0.4 с; сдвинулась - пробы вокруг пересчитываются. Переход ближняя → дальняя сетка - `_fade_cells` 5 (раньше резкая граница «тени прогружаются при подходе»). `_indoor_boost` 2.5 (бывший `_bounce_indoor`), `_fill` удалён, `_debug 6` - отражённое небо. Потоки: пул движка (`_threads` 1) быстрее собственного. **Ловушка**: заливка проб квадами идёт через очередь вызовов материальной системы (`mat_queue_mode 2`), у неё стек 16 МБ на кадр - все пробы обеих сеток разом (~14 МБ вершин) роняли игру в `materialsystem.dll` на первом кадре карты; заливка ограничена 1536 + 512 проб за кадр, ближние первыми.
- **GI без «подгрузки»** (2026-10-30; «затемнение и отражённый свет подгружаются чанками, при подходе дальний конец зала меняется»; два абзаца выше - прежние версии, сверять с кодом). Причины: дальняя сетка в 4 раза реже ближней (±1024) - её граница ехала по залу перед игроком; проба сначала шла с 32 лучами и доуточнялась проходами, отскоки пересобирались обходом слотов по порядку - блоки менялись один за другим. Теперь (`deferred_gi.cpp`, описание в шапке файла):
  - **сетки**: ближняя 64×64×16 (шаг 64, ±2048 ед., переход в дальнюю на последних `r_deferred_gi_fade_cells` 6 ячейках - с ~1660 ед.), дальняя 48×48×12 с шагом **128** (до 3072), дальше - оценка без проб; размеры - таблица `s_GridDesc`, шейдер берёт размер атласа из `vecDims` сетки;
  - **всё в фоне**: свои рабочие потоки (`r_deferred_gi_threads` −1 = логических/2 − 1, 1..3, приоритет ниже обычного; очередь заданий под мьютексом, пачками). Главный поток только принимает результаты (бюджет `r_deferred_gi_budget_ms`), планирует, пишет в текстуру: 0.3–1 мс в кадре при ходьбе, сдвиг сетки обходит только вошедшие слои (полный обход 65 тыс. слотов стоил 3–4 мс на шаг). Проба трассируется **всеми лучами сразу**: 192 в радиусе `r_deferred_gi_hq_radius` (1024), дальше `_rays_mid` (96, доуточняется при приближении), дальняя сетка `_rays_far` 64. Ожидающие пробы - список, отсортированный по расстоянию (подсчётом), фоновый обход (солнце, доуточнение, сбор отскоков, раунд «собрать всё» раз в `_sweep_interval` 3 с) - строками сетки в разбросанном порядке;
  - **что читает освещение плавно идёт за пробами**: CPU пишет в «целевой» атлас (точками `MATERIAL_POINTS`, `_upload_points`; не больше `_upload_max` 2048 проб ближней сетки за кадр, ×4 после загрузки/телепорта - запись стоит ~1 мкс на пробу на главном потоке), `deferred_gi_blend_ps30` каждый кадр подтягивает к нему «display»-атлас (пинг-понг, `_smooth` 0.4 с), новая проба проявляется за `_fade` 0.5 с. Новая ячейка в слоте тороидальной сетки узнаётся по штампу ячейки в плоскости 3 (.w) и пишется в первую очередь (иначе освещение прочитало бы пробу с другого края сетки); при прыжке сетки (телепорт, > ¼ проб) атласы очищаются;
  - **потоки и данные**: у пробы не больше одного задания (`bBusy`); задание пишет в свои поля, главный поток переносит (кроме солнечного - оно отмечает освещённые попадания своей пробы на месте); результат для старой ячейки слота отбрасывается по `gen`. Попадания - 8 байт (номер луча, дистанция 1/8 ед., октаэдральная нормаль, индекс альбедо в неперевыделяемом массиве). Brush-сущности - неизменяемый снимок со счётчиком ссылок. `DeferredGI_Reset` (выгрузка уровня) и выход сначала дожидаются всех заданий;
  - **цена**: первая заливка на загрузке 3–4.5 с (93 тыс. проб; `r_deferred_gi_load_ms` 6000, остальное - в фоне), ~30 МБ попаданий; освещение комнат `gi_test` - как у прежней версии (A/B снимков), `demo_map_rus`/смена карты/сохранение-загрузка - без вылетов;
  - **отладка**: `r_deferred_gi_stats` (потоки, задания, фазы главного потока «среднее / худшее за 2 с»), `r_deferred_gi_probe_info` (+ столбец проб над точкой: свободно вверх/вниз, небо, попадания), `r_deferred_gi_debug 7` позиция пикселя (frac/64; одна точка обязана выглядеть одинаково с любого места), `8` нормаль, `9` расстояние до `r_deferred_gi_debug_point "x y"`, `10` доля ближней сетки / вес её проб / небо ×10.
  - **Ловушки проверки**: (1) `startmovie` идёт ~6 кадров/с, фоновые потоки успевают всё - подгрузку так не увидеть: снимать окно в реальном времени (`capture_rt.ps1` навыка playtest: PrintWindow ~20 кадров/с между `echo CAPSTART` / `echo CAPEND` в шагах тура). (2) Яркость одной точки из разных видов различается из-за экспозиции кадра (а с `r_hl2rpm_post 0` включается экспозиция движка) - сравнивать отладочные выходы GI (`debug 10`), а не итоговый кадр. (3) Зал станции `rpm_trainstation_testoptimization` закрыт крышей: внутри небо ~0 у всех проб - тёмный пол в `debug 3` верен, светлее только у выхода.
- **Контактные тени**: длина марша - не больше 2 x `r_deferred_contact_shadows_texels` (8) текселей каскада в точке (иначе у каждой тени был ореол-«кусочек»), дизеринг шага - фаза TAA (`_dither` 1; без TAA шум выключен). В `lightingpass_global_ps30` первая часть `main` (тени) - в отдельном блоке, вторая перечитывает нормали `tex2Dlod`: иначе не хватает временных регистров (X4505).
- **Ореол солнца** (`r_hl2rpm_glare`, `hl2rpm_postfx_ps30` c8): мягкое свечение вокруг диска поверх того, за чем оно стоит. **Видимость солнца — по буферу глубины G-буфера на GPU** (2026-10-17, «ореол проходит сквозь листву и стволы»: трассы по миру не видят alpha-test листвы и тонких стволов): `hl2rpm_lum_ps30` PASS 2 (тот же 1×1, что адаптация глаза) считает долю неба (глубина 0) в диске солнца (центр + 8 точек на 0.35°), кольце 1.3° и ореоле 4° (веса 0.45 / 0.3 / 0.25), сглаживает её за ~0.1 с и пишет в канал `.b`; постпроход умножает на неё и блик, и ореол (`metering.b`). Позиция солнца и масштаб «uv на радиан» — `WeatherRender_GetSunScreenScale` (c1 прохода). Лучи: вторая, узкая доля фазовой функции в `volumpass_sun_ps30`, экранные god rays взвешены близостью к солнцу.
- **Погодный проход у воды**: `OnPostOpaque` (туман, мокрость) - полноэкранный квад, а с водой в кадре включена плоскость отсечения по высоте (`MATERIAL_HEIGHTCLIPMODE`) - часть кадра оставалась без тумана («fullbright» при погружении). Вокруг вызова режим отсечения выключается; вид преломления под водой тоже зовёт погодный проход.

- **Мир в картах теней — свои меши** (2026-10-12; `deferred/deferred_worldmesh.cpp`, `r_deferred_shadow_worldmesh` 0 движок / 1 каскады и карта дождя / 2 все теневые виды). У движка в `Shader_DrawChainsStatic` предел 127 «смен вершинного формата» за вид (новая запись при каждой смене статического меша мира между соседними группами материалов): теневой вид видит всю карту, на `map_v11` предел превышался — «Too many vertex format changes in frame, whole world not rendered», и часть мира не отбрасывала тени (мигало от шага камеры). Модуль читает грани мира из `.bsp` (в т.ч. дисплейсменты), строит статические меши по сетке 1024 ед.: непрозрачное — одним своим материалом `__hl2rpm_world_caster` (формат задаётся явно: у непрекэшированного материала формата нет, меш «нулевого» формата не лочится → `Error`), alpha-test — своими материалами. Отсечение — `engine->CullBox`. **`bShadowDepth` в `DrawExecute` — не «карта теней»**: G-буфер тоже зовёт с `true`; различать по `IsShadowMapView()`. Отладка `_show`, `_debug`, `_add`. **Ловушка — `CUtlMap` / `CUtlRBTree` по умолчанию с индексом `unsigned short`** (65 535 записей): карта рёбер окклюдеров (`edgeUse`) на `rpm_trainstation_testoptimization` (89 тыс. рёбер после правки 2026-11-03) роняла игру при загрузке — окно «CUtlRBTree overflow!»; для данных карты — `CUtlMap< K, V, int >` (так же `s_AlbedoMap` GI и `visited` генератора навигации). Остальные виды предел больше не задевает — списки мира сортируются по мешам (см. «Списки мира движка по мешам» в «Occlusion culling для открытого мира»).
- **Сканирование материалов не должно их загружать**: `GetShaderName()/FindVar()/IsTranslucent()` у «огрызка» материала прошлой карты форсируют загрузку → спам «CMaterial::PrecacheVars: error loading vmt». Без побочных эффектов только `IsPrecached()` — так сделан обход forward-материалов (`weather_render.cpp`) и `r_deferred_list_materials` (печатает ещё `$treesway`, `$pbr_transmission`, `$litface`, `$pom_heightmap`).
- **Parallax occlusion mapping** (2026-10-12/17; `r_deferred_pom`, `_scale`, `_distance` 1100, `_occlusion` 0.35, `_auto`, `_texture`, `_texture_normal`). Карт высот у стоковых материалов нет — клиент делает их при загрузке материала (`deferred/deferred_pom.cpp`, мип ≤ 256 по длинной стороне, прямоугольные степени двойки тоже; `r_deferred_pom_info 1` печатает каждую):
  - **из карты нормалей** (`_pom/<bump>`): наклоны −n.xy/n.z, интегрирование Пуассона через FFT. Знак зелёного канала стоковых карт — как в коде; переворачивается, только если другой знак даёт ротор меньше вдвое (у узора одного направления — доски, полосы — ротор одинаков, и прежнее «меньше — значит верно» переворачивало их наугад: на map_v11 4 из 25). Низкие частоты срезаны (2.5 периода), шум сглажен (σ 1.1 текселя), нормировка между 2-м и 55-м перцентилем — **лица кирпичей/плиток плоские, тонут только швы** (иначе «подушки»: плитка-арка, кирпич «в шерсти»);
  - **из самой текстуры** — у кирпича, камня, плитки, брусчатки, скал **без карты нормалей** (`IsReliefMaterial` в `materialsystem_passthru.cpp`; бетон, штукатурка, дерево, металл — нет: их тёмные пятна — грязь, а не вмятины). Таких в стоке много (49 кирпичных, 42 каменных, вся стена test_deferred `brick/brickfloor001a`): плоские при любом свете. Высота = яркость минус окрестность (1/16 текстуры), светлое выше — проверено на 174 стоковых материалах с настоящими нормалями (прототип `relief_proto*.py`): знак верный в 95 % уверенных случаев; светлая сетка швов, связная через всю текстуру (`HasLightJoints`: самый большой кусок светлых 30 % > 0.5 и больше тёмного на 0.1), — швы (tilefloor008a). Остальное — `scripts/hl2rpm_relief.txt` (копия в `hl2rpm_extras/scripts`): `invert` / `keep` / `none` по подстроке имени (`r_deferred_pom_reload_rules`). Размер до 512 (`r_deferred_pom_texture_size`: швы 512-й текстуры шириной в тексель-два, на 256 они расплывались в склоны), сглаживание 0.9 текселя, перепады сделаны круче (smoothstep 0.15–0.85: плавный край кирпича в текстуре при марше тянулся «мехом»), глубина ×0.6 (`$pom_texturerelief`), и материал получает ещё и **карту нормалей** из этой высоты (`_pomn/...`, RGBA с мипами, `$bumpmap`; `r_deferred_pom_texture_normal`) — свет и тень идут по рельефу.
  Глубина — таблица по имени (`PBR_GetReliefDepth`) × 0.4, т.е. 2–3 см. Марш (`hl2rpm_pom_fxc.h`) — от 8 шагов в лоб до 28 под скользящим углом + секущая; почти вдоль поверхности рельеф прижимается (полный до 70° от нормали, нет с 84°: луч, почти параллельный стене, тянул текстуру по каждой ступени рельефа в полосы — ракурс пользователя вдоль кирпичной стены test_deferred); высота точки попадания затемняет низ рельефа (швы) — `r_deferred_pom_occlusion`, c32.w композита. Одна функция в `gbuffer_ps30` (комбо `POM`, s7, c4) и `composite_ps30` (ветка по c32, s12) — сдвиги обязаны совпасть. Не для `$basetexture2`/бленда/декалей, не в 3D-скайбоксе и отражениях. ~0.8–1.5 мс на экран рельефа. **Ловушка**: `r_deferred_pom "scale"` (видимо, `r_deferred_pom scale …` в консоли) читалось как 0 и сохранялось в `config.cfg` — параллакс был молча выключен; теперь нечисло = 1 (с сообщением). Тест — `pbr_gallery`.
- **Ветер: деревья и трава** (`r_deferred_treesway`, `_strength`, `_speed`, `_calm` 0.16, `_leaves` 0.55, `_branches` 6, `_trunk` 0.4). Модели: статик-комбо `TREESWAY` в `gbuffer_vs30`/`composite_vs30`/`shadowpass_vs30` (`hl2rpm_sway_fxc.h`, константы VS c56/c57 — три прохода обязаны совпасть до бита: композит проверяет глубину G-буфера; тени качаются вместе с деревом). **Ствол почти стоит** (наклон верхушки `_trunk` ед. на 100 ед. высоты в сильный ветер — «стволы шевелятся как листва» было при общем изгибе всего дерева), **качаются ветви** — тем сильнее, чем дальше от оси ствола (ось z модели; у ствола 0, полностью — дальше 176 ед.), каждая в своём ритме по направлению от ствола и высоте (гладкая функция направления: фаза по `atan2` рвала карточки ветки на линии его разрыва), на концах — дрожь листьев. Материалы листвы — `$treesway 2`, ствола — 1 (только наклон). Ветер — наклон дождя погоды (`weatherData_t::vecWind.zw`). `$treesway` ставит клиент материалам растительности (`IsSwayMaterial` в `materialsystem_passthru.cpp`; driftwood/rock/stump/log — нет). **Ловушка**: копии стоковых материалов деревьев от Mapbase содержат `$treesway 0` (его собственное качание — для скинов `_sway`) — проверка «ключа нет» не срабатывала, деревья стояли; теперь ставится всегда, `$treesway -1` в VMT — запрет. Трава (detail-спрайты) — на CPU в `detailobjectsystem.cpp` (`DetailWindSway`: верхние вершины быстрых спрайтов).
- **Просвечивание листвы и ткани** (`r_deferred_transmission`, `_power` 3, `_tint` 0.65, `_glow` 2, `_composite` 0.3; `$pbr_transmission`; `r_deferred_foliage_light` 0.7, `_depth` 100): листва (alpha-test материалы растительности) получает `$litface 1` (свет с обеих сторон). **Свет сквозь крону** — в проходе солнца (`lightingpass_global_ps30`, c80): для litface-пикселей затенённая часть получает `доля листвы среди блокеров × exp2(−глубина/100 ед.) × 0.7` солнца (глубина — до тенеобразователей из поиска блокеров PCSS; только ближние каскады, где есть поиск). **Листва помечена в «сырой» глубине атласа солнца**: `shadowpass_ps30` прибавляет c1.x = 2 у litface-тенеобразователей (`defpass_shadow.cpp`, на каждый draw; только каскады солнца — карта дождя и лампы получают 0), поиск блокеров декодирует `frac( raw·0.5 )·2` и считает листья как `raw − d` — свет идёт сквозь листья, но не сквозь стену, крышу или ствол (раньше куст в тени стены в 50 ед. получал ~23 % солнца). Другие формы этого декодирования (`step`, `float3`-аккумулятор, `[loop]`) и любой отладочный вывод листвы в этом шейдере дают **X4505** — регистров нет совсем. **Свечение против солнца** (2026-10-17, «не вижу подсветку листвы»): в проходе солнца к свету листа добавляется `дошедший свет × r_deferred_transmission_glow × (cos^3 + 2·cos^18)` угла «взгляд — солнце» (композит умножает на альбедо — свечение в цвет листа); прежний множитель композита (c33/c34, `1 + T·(…)`) оставлен на 0.3 — только оттенок. Против низкого солнца ветки светятся жёлто-зелёным; когда солнце за плотной кроной — светится край кроны и просветы, середина остаётся тёмной, как в жизни. Двусторонняя ткань моделей (curtain/cloth/tarp/flag…) — 0.3.

Надмножество — карта теней та же.
  - **Кэш теней прожекторов** (`deferred/deferred_shadowcache.cpp`, `r_deferred_shadow_cache`, `_spots` 12 карт 2048² ×16 бит = 96 МБ, `_debug`, `_maxage`): у затенённого прожектора своя карта из пула (`_rt_defShadowCacheProjNN`), слот прохода света получает её через `CommitTexture_ProjectedDepth`. Вид собирает рендереблы каждый кадр, рисует, только если изменились лампа (позиция, углы, радиус, FOV, разрешение, исключение) или подпись рендереблов (указатели, позиция, углы, модель, альфа, эффекты, последовательность/цикл/поза/скин/боди); NPC, игрок, рэгдоллы и качающиеся модели (`$treesway`) — каждый кадр. Сброс — смена карты, восстановление RT, изменение настроек смещения. Точечные лампы (кубы) не кэшируются.
  - **Небо** (`procsky_atmo_ps20b.fxc`, `skyatmo_proc.cpp`, `r_deferred_sky_skip_covered`): рисуется первым без теста глубины — шейдер считал весь экран. В основном виде (задний буфер, вьюпорт = G-буфер, не отражение) пиксели с геометрией в G-буфере выходят сразу; звёзды — за ветвлением (`$starsintensity 0` у всех небес мода); все выборки `tex2Dlod` (цели без мипов). −1.1…1.5 мс.
  - **Лампы**: в `lightingpass_spot/point_ps30` фильтр тени 5×5 (25 сравнений) только где `lightAmount·fade > 0` (иначе результат от тени не зависит); `ShadowDepth_*_Nvidia` на `tex2Dlod` (без мипов — то же). −0.5 мс.
  - **Солнце**: цикл выбора каскада 8 → 4 (`SUN_SHADOW_CASCADES`; активных не больше 4, остальные нулевые). Сам проход ~2240 инструкций/пиксель — дорогие части (PCSS, геометрическая нормаль, контактные тени) — видимое качество.
  - **Пост движка** (`viewpostprocess.cpp`, `r_hl2rpm_engine_post_skip`): гистограмма, блум и проход `engine_post` пропускаются, когда экспозицию и блум ведёт наш пост, а цветокоррекции и эффектов `postprocess_controller` нет. −0.65 мс.
  - **Списки мира** G-буфера кладутся в кэш движка (`r_deferred_gbuffer_listcache`), композит того же вида их берёт.
  - **Масштаб рендера + TAA-апскейл** (`r_hl2rpm_renderscale`, по умолчанию 0.75; меню «Графика», пресеты: 50/67/75/75/75 %; применяется при пересоздании целей — вне карты / при запуске): `RenderView` рисует 3D в `_rt_hl2rpm_scene` (через `g_pMain3DViewTarget` в `SetupMain3DView`), все экранные deferred-цели создаются `CreateFrameSizedRT` (при масштабе — `RT_SIZE_LITERAL` размера кадра, иначе прежние `FULL_FRAME_BUFFER_ROUNDED_UP`/`HDR`), SSR/зеркала читают копию `_rt_hl2rpm_scenecopy`. `DeferredTAA_DrawUpscale` (`hl2rpm_taau_ps30`): маска «движется с камерой» из бита трафарета (`_rt_hl2rpm_upscalemask`, общий depth-stencil), затем в задний буфер: 3×3 сэмпла кадра с весами `exp(−k·d²)` по расстоянию их джиттеренных позиций до центра пикселя экрана (`r_deferred_taau_sharpness` 2.29, знаки джиттера `r_deferred_taau_jitter_sign "1 -1"`), история полного разрешения по глубине, клип YCoCg; пост, затемнения и HUD — после, в полном разрешении (`postView`); без TAA — билинейное растяжение. Сдвиг мипов композита −0.5 + log2(масштаба). Окно настроек выше на 64 px (13 строк). **Ловушка**: `mat_viewportscale` deferred не поддерживает (проходы читают цели как 0..1 вида) — не путать с этим масштабом.
  - **Итог 1080p «Ультра» + 75 %**: вокзал 20–24 мс (было ~35), `building_test` ~19 мс (было 27), `water_test` ~17 мс (было 22). Остаётся: на больших картах CPU рендера ~17–20 мс (каскады 4 вида с пропами каждый кадр, сцена рисуется дважды), GPU — солнце, каскады (R32F-цвет пишется для всех 4), GI, лучи.

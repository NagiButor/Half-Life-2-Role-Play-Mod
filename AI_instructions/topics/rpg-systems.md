# РПГ-системы: предметы, лут, замки, торговля, логика и задания, персонаж, терминалы, общие темы, кражи

> Общая техническая справка для любой AI-модели. Правила — `../PROJECT.md`, статус — `../CURRENT_STATUS.md`. Процедура — `../skills/hl2rpm-dialogs/SKILL.md`. Источник контента CK — `.hl2dlg`, сгенерированные игровые файлы не редактировать без обратного импорта.

- **РПГ-слой** (2026-10-31, M2): база предметов `scripts/rpg/items.txt` и списки лута `scripts/rpg/lootlists.txt` (вкладка «Предметы»; `game/shared/hl2rpm_items.*` — клиент и сервер). Предметы с `base` (note/key/currency/generic) — сущность `item_rpm` (`hl2rpm_item_entity.cpp`), записка — окно `rpm_note_open`. `list:<id>` в луте разворачивается при первом открытии (`RPMLoot::Resolve`). Замки контейнеров (`lock_key`, `lock_level`, `restock_hours`) и дверей (`rpm_key`, `rpm_lock_level`) — `RPMLock::TryOpen`. Состояние РПГ (`RPMState`: флаги, переменные, игровые часы и дни, торговцы) — одно дерево KeyValues в своём блоке сохранения (`hl2rpm_rpg.cpp`). **Шаблоны NPC** (`template`, `is_template`): пустые поля берутся из шаблона при экспорте; **вариации** — `models`, `weapons` (пустой элемент = без оружия), `names` (`female 1` — для моделей с female/alyx/mossman), `skin_max`, `proficiency`, `xp`. **Точка появления** `rpm_spawner` (`hl2rpm_spawner.cpp`): держит count_min..max живых из списка `npcs` (`def:вес;класс`) вне поля зрения игрока, пополнение через `respawn_hours`. **Торговля**: блок `vendor` в `scripts/npcs` (list, money, markup, pays, restock_hours, currency = `rpm_credits`), вариант диалога `trade 1`; окно лута в режиме торговли (`kInventoryUpdate_TradeInfo`; «взять/положить» = купить/продать, групповые команды в торговле игнорируются), запас и деньги — `RPMState` "vendors". **Переходы между картами** (ref `transition`: `target_map`, `target` — парный переход там, `size`, `arrive`/`arrive_yaw` = перед дверью по её повороту): сервер сам ставит `info_landmark` ×2, `trigger_changelevel` (касание + «связь» без касания) и `trigger_transition` ×2 — **без брашей и без пересборки** (коробочные триггеры: ключи `rpm_box_mins/maxs` в `CBaseTrigger`/`CTriggerVolume`). Переходы создаются раньше слоя (`RPMWorld::SpawnTransitionsEarly` в `CServerGameDLL::LevelInit` до `LoadAdjacentEnts`: `LevelInitPostEntity` идёт после него). **Ловушка**: сущность без браш-модели движок переносит через переход (`FCAP_ACROSS_TRANSITION`) — коробочный `trigger_changelevel` приезжал под игрока и срабатывал снова; `CBaseTrigger::ObjectCaps` его снимает. Консоль: `rpm_give <id> [n]`, `rpm_trade <npc>`, `rpm_vendor_dump`, `rpm_state_dump`, `rpm_flag`, `rpm_var`, `rpm_loot_roll <list>`. Шрифт `Trebuchet24` ClientScheme — только латиница (заголовки на русском пустые).
- **Логика CK** (2026-10-31, M3; сервер `hl2rpm_logic.cpp/.h`, CK `dlgedit/logic.py`, `ui/logic_widgets.py`, `ui/logic_pages.py`, `ui/quest_widgets.py`): **условия** (блок `"conditions" { "c" { "type" … "not" "1" "or" "1" } … }`: quest_state/quest_stage/objective, flag, var, item, skill/stat/level, rep, time, day, weather, map, zone, near, alive, hostile, talked, health, suit, event, chance) и **действия** (`"actions" { "a" { "type" … "delay" N } }`: give/take/money/xp, flag/var, quest_start/stage/objective/complete/fail, rep, hostile/faction_hostile, message (`text_<язык>`), sound, teleport, dialog, trade, kill, remove, fade, time, weather, skill/stat, fire (ввод сущности), command) — одни везде: варианты ответа (`conditions`, `show_unmet`, `check {skill|stat value}` + `fail_next`/`check_once`/`fail_actions`, `actions`), реплики (`actions`), пакеты распорядка, refs слоя (**присутствие**: объект создаётся/убирается по условиям, состояние — `RPMState` "presence", убитое/взятое не возвращается, NPC не исчезает на глазах), события `scripts/rpg/events.txt` (`on`: map_enter, zone_enter/leave, kill, use, talk, hour, quest_start/stage/complete/fail, when; `once`, `delay`, `map`), флаги/переменные новой игры `scripts/rpg/globals.txt`. Действия, которым нужно закрытое окно диалога (hostile, teleport, trade, dialog, kill), ждут клиентского `dialog_closed` (шлёт `CVGuiDialogPanel::EndDialog`). **Задания** — `scripts/rpg/quests.txt` (CK больше не пишет квесты в файлы диалогов; сервер читает оба, quests.txt важнее): у этапа `objectives` (kill/collect/talk/go/use/cond/custom; прогресс — `RPMState` "qobj" `<quest>.<obj>`), `actions` (при начале), `next`, `final`; у задания `xp`, `on_complete`, `on_fail`, `fail_conditions`. Цели — строки журнала (описание этапа идёт сообщениями `kQuestsUpdate_QuestDescMore`: user message держит 255 байт) и **маркеры HUD** (`rpm_markers` → `hl2rpm_markers.cpp`, элемент `HudRPMMarkers` в HudLayout.res, шрифт Trebuchet18 — с кириллицей). Варианты: флаги клиенту 2 — серый (условия не выполнены), 4/8 — проверка проходит/нет (цвет), метка «[Красноречие 50]» в тексте. **Зона** — ref `zone` (коробка `size`, поворот по yaw). Тест-состояние — `rpm_test_state <файл>` (CK «Игра → Состояние для запуска» пишет `scripts/rpg/test_state.txt`). `rpm_credits` — встроенная валюта (стопкой, вес 0, «Жетоны») и без базы предметов. Консоль: `rpm_logic_debug 1/2`, `rpm_events_dump`, `rpm_skill`, `rpm_journal` (журнал), `quest_dump`. CK: автоперевод Google без ключа (`dlgedit/translate.py`, пометка «МП» — хэши в `project.mt_marks`), симулятор F5 с флагами/навыками/предметами. **Ловушка тестов CK**: тесты, создающие `MainWindow`, обязаны ставить `HL2RPM_CK_SETTINGS` — иначе их временные проекты становятся «последним проектом» пользователя.
- **РПГ-персонаж** (2026-10-31, M5; общие описания `game/shared/hl2rpm_rpgdefs.*` (клиент и сервер), сервер `hl2rpm_char.*`, клиент `hl2rpm_charpanel.cpp`; CK `dlgedit/rpgchar.py`, `ui/char_pages.py`, вкладка «РПГ»). `scripts/rpg/rpg.txt`: `rules` (stat_total 40, tags 3, tag_bonus 15, skill_base 2 + skill_per_stat 2 × своя + ⌈Удача / 2⌉, points_base 10 + Инт × 0.5, perk_every 2, level_max 30, опыт FNV 25·(3L+2)(L−1) × xp_scale, здоровье 50 + 10 × Вын + 3 за уровень, вес 25 + 3 × Сила кг — при всех 5 как у HL2: 100 HP и 40 кг; урон по навыку оружия 0.75..1.25, крит Удача %, лечение + Медицина × 0.005, цены ± Бартер × 0.002, опыт за врага / взлом / проверку, репутация), `stats`/`skills` (названия, `stat` навыка), `perks` (`level`, `ranks`, `req`, `effects`), `traits`; без файла — встроенные 7 характеристик, 12 навыков и правила, перков нет. Эффекты: stat, skill, skills, hp, carry, damage (id = навык оружия), crit, heal, xp, price, points, dr. Состояние — `RPMState` "player" (`stats` — выбранные, `skills` — **добавленные очки** поверх формулы; `rpm_skill` и тест-состояние задают итог через `RPMChar::SetSkillTotal`), "rep" (репутация фракций; убийство не враждебного члена фракции −rep_kill, ≤ rep_hostile — фракция нападает, имя — `RPMWorld::FactionName`). Точки подключения: `CBaseEntity::TakeDamage` → `RPMChar::ModifyDamage` (навык оружия по `items.txt` "skill", DMG_BLAST — взрывчатка), `CBasePlayer::TakeHealth` × `HealScale`, `InventorySystem::GetPlayerMaxCarryWeight` (конвар `sv_inventory_weight_max`, если изменён, важнее), цены `loot_system.cpp`, опыт за взлом `RPMLock::TryOpen` и за проверку `dialogsystem_server.cpp`; `RPMLogic::AddXP` → `RPMChar::AddXP` (уровни, очки, перки, стингер `level_up`). Клиенту — user message `RPMChar` (KeyValues текстом кусками ≤ 200 байт, флаги 1 начало / 2 конец), окна — `rpm_char_open create|levelup|sheet`, `rpm_character` (лист). Сервер сам открывает повышение уровня раз на уровень вне боя (`RPMAudio::InCombat`), клиент откладывает его до конца диалога и окна создания. **Новая игра** — `scripts/rpg/newgame.txt` (`map`, `spawn`, `yaw`, `create`, `name`, `actions`; применяется один раз при `MapLoad_NewGame`, флаг "player"."newgame_done"); «Новая игра» меню — `cfg/chapter1.cfg` (CK пишет по кнопке). Логика: условия `perk`, `created`, `rep` с `faction`; действия `perk`, `char_create`, `rep` с `faction`. Консоль: `rpm_char_dump`, `rpm_char_debug 1`, `rpm_xp`, `rpm_perk`, `rpm_rep`, `rpm_char_create`. **Ловушка тестов**: `run_game.ps1` пишет шаги не в UTF-8 — кириллицу в командах подавать через свой `cfg/*.cfg` в UTF-8 и `exec`; `save` в тесте оставляет `save/<карта>.HL1..3`.
- **Взлом замков и терминалы (M6.5)** (2026-11-01, по просьбе пользователя «как в Fallout»). **Замки**: `RPMLock::TryOpen` (`hl2rpm_rpg.cpp`) у замка с уровнем (контейнер `lock_level`, дверь `rpm_lock_level`) запускает мини-игру — сервер `hl2rpm_lockpick.cpp` выбирает «сладкую точку» 0..180° и её ширину (уровень против навыка «Взлом»), клиент `hl2rpm_lockpick_ui.cpp` играет (мышь / стрелки — шпилька, A / D / ЛКМ / пробел — поворот, F — силой, Esc) и отвечает `rpm_lockpick_report <token> broke|open|force|cancel`. Поломка тратит `bobby_pin` — встроенный предмет, как `rpm_credits` (`RPMItems::IsBuiltin`: вес 0, стопкой, модель `models/hl2rpm/items/bobby_pin.mdl`; в CK — «…» стандартных предметов). Открытый — открыт навсегда (RPMState "unlocked"), неудача «силой» — "jammed" (только ключ; в подсказке под прицелом флаг 4 — «Заклинило»), опыт — раз за замок ("picked"). Навык ниже «уровень − 25» — «Нужен навык». `rpm_lockpick 0` — старая автопроверка. Консоль: `rpm_lockpick_debug 1`, `rpm_lockpick_reset`, `rpm_lockpick_key pin|off|turn|force|esc`. **Терминалы**: `rpm_terminal` (`server/hl2rpm_terminal.cpp`, клиент `hl2rpm_terminal_ui.cpp`, FGD `hl2rpm.fgd`), содержимое — `scripts/rpg/terminals.txt` (CK: «Логика» → «+ терминал»; на карте — объект слоя `terminal` с `"terminal" <id>`): стиль pc / combine, название, приветствие, записи (текст; его `actions` — при первом прочтении), команды (`actions` + `result`), подменю, `conditions`, `once`; замок `lock_level` / `lock_skill` (science) / `password_item`. Экран модели — таблица `s_TermScreens` (monitor01a, combine_intmonitor001 / smallmonitor001 / interface001), иначе ключи `screen_pos/ang/size` или грань +X. Взлом — словами Fallout на клиенте: длина 4–12 по сложности, встроенные списки RU / EN, 2 × 16 строк × 12 символов, скобки убирают ложное слово / возвращают попытки, попыток 4 (3 — навык ниже сложности, 5 — выше на 25), блокировка навсегда; RPMState "terminals" (1 взломан, 2 заблокирован), "terminals_once"; опыт — правило `xp_hack`. Шрифты `RPMUI_Mono*` (Lucida Console, непропорциональные). Консоль: `rpm_terminal_debug 1`, `rpm_terminal_reset`, `rpm_terminal_use [имя]`, `rpm_terminal_key up|down|left|right|enter|back|leave|win|fail`, `cl_rpm_terminal_debug 1` (рамка экрана). **Ловушки**: (1) `ShouldDraw` клиентской рендер-сущности не должен зависеть от вида — лист-система спрашивает его только в `UpdateVisibility` (экран «пропадал» до смены сетевых данных), проверка дистанции — в `DrawModel`; (2) у панели в 3D «вправо» зрителя — +Y рамки экрана (обратный знак — зеркальная панель: текст отсекается как задняя грань, прямоугольники остаются); (3) VGUI `DrawTexturedPolygon` отсекает обратный обход — `RPMUI::Poly` сам разворачивает вершины; (4) `sed -i` в Git Bash снимает CRLF.

# HL2RPM Creation Kit: редактор, окно карты, превью, демо ck_test

> Общая техническая справка для любой AI-модели. Правила — `../PROJECT.md`, статус — `../CURRENT_STATUS.md`. Новые знания по теме добавлять сюда. Упоминания Claude в названиях меню и каталогов — существующие подписи программы; эти функции доступны любому AI-агенту. Для отчётов снимать только окно/виджет: старый `--shot` может захватить чужие окна.

## HL2RPM Creation Kit (редактор контента, бывший Dialog Editor)

Пользователь наполняет открытый мир в своей программе «по типу GECK» (2026-10-30): `E:\SourceModding\HL2RPMSOURCE\HL2RPM Creation Kit\HL2RPM Creation Kit.exe`; исходники — `hl2rpm_extras/tools/dialog_editor` (Python 3.14 + PySide6 + PyOpenGL, точка входа `hl2rpm_creation_kit.py`, сборка `build_editor.ps1` → PyInstaller, venv в `E:\SourceModding\HL2RPMSOURCE\dialog_editor_build`), подробности — README там и навык `hl2rpm-dialogs`. Тестовый проект — `E:\SourceModding\HL2RPMSOURCE\dialogsrc\test_dialogs.hl2dlg` (папка игры `hl2rpm\testmaps`), тестовая карта мира — `ck_test` (генератор `hl2rpm_extras/tools/make_ck_test.py`, VMF в `mapsrc\test`).

- Проект `*.hl2dlg` (JSON) — источник правды; Ctrl+S пишет файлы игры с заголовком `// HL2RPM Creation Kit: generated` (старые — `HL2RPM Dialog Editor: generated`; руками такие файлы не править): `scripts/dialogs/<npc>.txt` (только у NPC с репликами), WAV → `sound/dialogs/<npc>/<язык>/`, сцены с липсинком → `scenes/dialogs/<npc>/<язык>/`, **`scripts/npcs/<npc>.txt`** (персонаж и распорядок), **`scripts/world/<карта>.txt`** (что поставлено на карту), **`scripts/world/<карта>_nav.txt`** (узлы навигации), **`scripts/world/factions.txt`**. Файл → «Импорт мира из игры» читает их обратно.
- **Окно карты** — 3D-вид скомпилированного BSP (мир, дисплейсменты, статические пропы, NPC из Hammer) по путям поиска `gameinfo.txt` мода (VPK тоже, `dlgedit/world/`: `vpk.py`, `gamefs.py`, `bsp.py`, `vtf.py`, `materials.py`, `mdl.py`, `scene.py`; рендер — `ui/worldview.py`, `ui/render_gl.py`). Карты ищутся как в игре: `hl2rpm\maps` затеняет `testmaps\maps`. Снимок виджета (`grab()`) не захватывает подписи поверх 3D — режим `--shot` снимает экран.
- **Языки в одном файле**: обычные ключи — основной язык, `<ключ>_<язык>` — перевод и своя озвучка (`line_russian`, `choreo_russian`; присутствующий пустой ключ = «на этом языке без звука»). Сервер берёт язык из `dialog_language` (пусто → `cl_language` → Steam; здесь `russian`), смена конвара перечитывает диалоги. `display_name` файла диалога — имя в окне диалога и лута (важнее `loot_displayname` из Hammer); у NPC без диалога — `display_name_<язык>` его `scripts/npcs`.
- Поведение сервера, изменённое вместе с редактором диалогов (`dialog_definitions.cpp`): `returning_auto_next` без `returning_no_options` выбирает реплику, чьи варианты идут после повторной реплики (раньше игнорировался — узел 12 demo_npc_2 был недостижим); повторная реплика и `after_line` играют только свою озвучку; `auto_close` = `end`; `dialog_reload` не чит.

- **Окно карты как Hammer++** (2026-10-31, M1 плана `peppy-mapping-wreath`): Z — полёт, гизмо (стрелки/плоскости; короткий ПКМ по выделенному — кольца поворота), рамка, Ctrl+C/V, End — «приземлить» (лучи из нижних вершин модели вниз). Пропы/сущности **из VMF** правятся в CK (`dlgedit/world/vmfdoc.py`: правка только изменённых блоков, `.bak_<время>`; VMF ищется в `mapsrc`/`mapsrc\test`), **F9 — сборка** `hl2rpm_vbsp/vvis/vrad` (только сущности — `-onlyents`), копия прошлого BSP — `E:\SourceModding\HL2RPMSOURCE\map_backups`. Вкладка «Модели» (миниатюры — кэш `%LOCALAPPDATA%\HL2RPM Creation Kit\thumbs`), автосохранение раз в 5 мин. Выпадающие списки не должны пересоздавать страницу при открытом списке — `insp.rebuild_soon()`, `bind_combo` (`world_pages.py`).
- **Превью в CK (M7)** (2026-11-01). **Анимации** — `dlgedit/world/anim.py`: кости MDL (`mstudiobone_t` 216 байт), последовательности модели и включённых `$includemodel` (кости сводятся по именам), разбор сжатых анимаций (RLE-значения, Quaternion48/64, Vector48, `.ani`-блоки и секции), матрицы костей × poseToBone, скиннинг numpy по весам VVD (`Mesh.bw/bb` в `mdl.py`; кадр горожанина ~2 мс). Берётся первая анимация последовательности — без поз-параметров, слоёв и IK. **Ловушка Mapbase**: `male_shared` объявляет одноимённые последовательности заранее пустыми (`STUDIO_OVERRIDE` 0x0800, анимация `@reference`), настоящие — в `male_shared_original` / `*_original`: при сборке набора заготовка заменяется следующей одноимённой (иначе сидение и ACT_IDLE были бы стоячей опорной позой). Активность — по имени (`find`: имя, иначе первая с такой ACT_). **Окно «Просмотр модели»** (`ui/model_viewer.py`, `render_gl.SkinnedMesh` — свой динамический VBO, индексы `ModelMesh`): список с поиском, проигрывание, кадр, скорость, кости, скин; из ПКМ по NPC / пропу / маркеру на карте и кнопки «Анимации…» у модели NPC. **Окно карты**: «Показать → Анимации NPC» — NPC проекта на маркере пакета выбранного часа играют его анимацию (`actbusy.txt`: `busy_sequence` / `busy_anim`), иначе ACT_IDLE (`world_ctrl.npc_preview_sequence`, `marker_of_package`). **Свет** — «Показать → Освещение» и «Ночь»: `world/lights.py` (light_deferred(_spot): diffuse × альфа, radius, power, конус — полный угол; классические light / light_spot: `_light`, `_distance`, `_cone`) и солнце часа (направление от `light_environment` / `light_deferred_global`, высота по часу, тёплое на закате), шейдер `FS_MESH` (`uLightMode`, до 32 ближайших ламп, конус, затухание `(1 − d/r)^power`), кубические карты расстояний R32F для 4 ближайших ламп с тенью (`render_gl.ShadowCube`, только мир, перерисовка при сдвиге лампы). **Ловушки**: (1) QPainter подписей оставляет состояние GL (запись глубины выключена) — рендер в свой FBO внутри `paintGL` сначала выставляет depth mask, depth test, scissor, stencil, blend, иначе куб оставался пустым; (2) **нормали мира CK**: vbsp пишет в `planenum` собственную плоскость грани (`side` — лишь чётность), а `bsp.py` переворачивал нормаль у граней с `side` — и шейдер переворачивал нормали по `gl_FrontFacing`, хотя обход граней Source противоположен GL; ошибки частично гасили друг друга (земля ck_test всегда была тёмной). Теперь нормаль — плоскость грани, а к зрителю её поворачивает `dot(n, uCam − vW)`. (3) Тесты CK, снимающие экран (`grabWindow`), захватывают окно сверху — снимки для отчётов только `widget.grab()`; тесты M1 «Z-обзор мышью» и порог сдвига гизмо зависят от фокуса окна и курсора.
- **Мебель, манекены, демо ck_test** (2026-11-01, после M7 по просьбе пользователя). **Игрок садится, как в New Vegas** (`server/hl2rpm_seat.cpp`, клиент `hl2rpm_seat_cam.cpp`): маркеры CK видов sit / eat / ground / sleep / lean (ближайший в 140 ед. по горизонтали и 64 по высоте, не дальше 46 от точки взгляда; не перехватывает USE у NPC, дверей, лута, терминалов, предметов, `func_*`) дают подсказку «[E] Сесть / Лечь / Прислониться» с именем мебели (ключевое слово модели ближайшей мебели в 64 ед.: Диван, Кровать, Стул, Кресло…; иначе по виду маркера — Стул, Стена…). Мебель карт — обычно `prop_static`, это не сущности: их перечисляет трасса-хулл с фильтром `TRACE_EVERYTHING_FILTER_PROPS` (только с ним `ShouldHitEntity` видит статические пропы; модель — `enginetrace->GetCollideable` → `modelinfo`), `EnumerateEntities` их пропускает — раньше диван ck_test назывался «Стул». Предмет на мебели важнее: пока на кровати лежит записка, E берёт записку. E — тело `rpm_seat_actor` (модель игрока, иначе male_07) играет вход → цикл → выход из actbusy маркера (`ActBusy_GetAnimParts` в `ai_behavior_actbusy.cpp`), игрок — EF_NODRAW, MOVETYPE_NONE, без оружия; хинт занят (чужой — «Занято»). Камера — третье лицо за головой тела (`rpm_seat_cam <ent> <verb>` клиенту, орбита по углам взгляда, `cl_rpm_seat_cam_dist` 90, трасса против стен), без вьюмодели и прицела; встать — E («[E] Встать»), прыжок, шаг, присед (через 0.6 с). Загрузка сохранения сидя: тела удаляются, игрок восстанавливается кадром позже. Консоль: `rpm_seat`, `rpm_seat_debug`, `rpm_seat_use`, `rpm_seat_at <маркер>`. **Манекены CK** (`worldview._mannequin`, «Показать → Манекены на маркерах», включено по умолчанию, как в GECK): на каждом маркере ближе 2500 ед. фигура (модель владельца, иначе male_07) играет анимацию маркера (`anim`, иначе по виду `DEFAULT_MARKER_ANIM`), одна поза на (модель, последовательность) за кадр — так видно, как тело ляжет на мебель, и манекен совпадает с игрой (проверено). Так найдены ошибки расстановки ck_test: `sitcouch1` сажает таз на 24 ед. позади маркера (маркер стоял в центре дивана — и в игре тело сидело за спинкой; теперь `ck_couch` на x 904), `laycouch1` лежит вдоль оси Y маркера (лежал поперёк кровати; `ck_bed` повёрнут на 270°). Объекты слоя `entity` рисуются моделью (`scene.ENTITY_MODELS`: турели, камера), предметы базы — своей `model` (без неё — clipboard). **Меню на Tab** звучит старыми звуками пользователя (`InventoryClient_PlayPanelSound` в `vgui_inventorypanel.cpp`: `zipline_clothing1/2`), не звуками UI HL2. **USE по мелочи на мебели**: `item_rpm` с `FCAP_USE_IN_RADIUS` — тонкий ключ на ящике: трасса прицела через кадр попадала в ящик, и цель USE (и подсказка) мигала каждые 0.1 с (подсказки не было видно); `rpm_prompt_debug 1` печатает каждую отправленную подсказку (сущность, глагол, имя). **Демо на ck_test остаётся** (пользователь: «потестил и всё удалил»): `hl2rpm_extras/tools/ck_demo_content.py [--export]` добавляет в `dialogsrc/test_dialogs.hl2dlg` (бэкап до демо — `test_dialogs.hl2dlg.bak_20261101_024906`) шкафчик склада `ck_storage` (#31: Взлом 50, ключ `key_storage` на ящике за домом), ящик с хламом (список `ck_junk`: шпильки, жетоны), записку `note_caretaker` на кровати (пароль терминала), ПК `office_pc` на кухонном столе (Наука 50 / записка; дневник, приказы, «Отпереть шкафчик» — действие door unlock), пост Альянса в юго-западном углу (консоль `sector17` Наука 25, турель `ck_turret` + `ai_relationship` с горожанами карты **D_LI** — именно «нравится»: `CNPC_PlayerCompanion::IRelationType` боится любой активной турели, если отношение не D_LI, и с D_NU оба рабочих навсегда стояли «в бою» со страхом — распорядок не шёл; проверка — `rpm_world_dump` (`blocked: combat`), баррикада `ck_field`, тайник), задание `ck_storage` (цели go + collect `storage_ledger`) по событию `map_enter`; refs 40–59. **Ловушка тестов CK**: тесты, копирующие проект пользователя (t_m3, t_m65), ждали проект без событий и терминалов — берут копию до демо.

## Hammer++ в CK и карта без компиляции (2026-11-04)

- Окно карты → кнопка **«Hammer++ ▾»**: «Открыть карту в Hammer++» (`bin\hammerplusplus.exe <vmf>`), **«Геометрия из VMF (без
  компиляции)»** (выбор хранится в `project.view["_geometry"]`), «Открыть VMF (набросок без BSP)…», «Задачи для Claude на этой карте…»
  (двойной щелчок — камера к задаче), «Снимки карты для Claude» (`<папка VMF>\_claude_shots\<карта>`).
- Геометрия из VMF — `dlgedit/world/vmfgeom.py` (`VMFMap`, то же устройство, что `bsp.BSPMap`: пачки по материалам, вода, сущности,
  границы, треугольники): каждый браш режется из плоскостей сторон (как vbsp: большой многоугольник на плоскости, отсечение остальными;
  нормаль `(p0−p1)×(p2−p1)`), UV из `uaxis`/`vaxis` и размера VTF, дисплейсменты из `dispinfo` (сетка от угла `startposition` + нормали ×
  расстояния + смещения + `elevation`). Сверено с BSP: ck_test — стены/пол совпадают до 0–0,2 ед., gfx_showcase — 36 дисплейсментов
  вершина в вершину (0,00), обход граней как у vbsp. ~1,8 с на 800 брашей. Инструментальные (`tools/*`) не рисуются, триггеры тоже.
- `MapScene(..., geometry="vmf")`; карты без BSP (наброски) в списке с пометкой «набросок (VMF)» и открываются в этом режиме сами.
  Пока режим включён, таймер (1,5 с) замечает сохранение VMF в Hammer++ и перестраивает карту, камера остаётся.
- Метки задач (`rpm_claude_task`, `func_rpm_claude_area`) — оранжевые коробки/звёзды и подписи «AI: имя · статус · текст» (`worldview`).
- **Снимки без игры** — `dlgedit/world/vmfshot.py` (`python -m dlgedit.world.vmfshot <vmf> <out>`; обёртка в навыке hl2rpm-hammer
  `scripts/vmf_shot.py`): 2D как в Hammer (сетка, контуры брашей, сущности точками, задачи), 3D — программный z-буфер с отсечением по
  ближней плоскости (цвет = средний цвет текстуры материала по DXT-блокам), крупные планы каждой задачи, `info.json`. ~2 с.
- Снимок окна самого Hammer++ — навык `scripts/hammer_shot.py` (PrintWindow одного окна, самое большое окно с «Hammer» в заголовке).
  При запуске Hammer++ может спросить про обновление (окошко «Hammer++ Autoupdater»): главное окно появится после ответа пользователя.
- Hammer-форк `source_level_editor` (Cvoxalury) сделан из слитого кода — не использовать (см. leaked-source.md).

### Совместимость AI-меток

Исторические классы `rpm_claude_task` / `func_rpm_claude_area`, каталог `_claude_shots` и пункты «Задачи/Снимки для Claude» не связаны с API конкретной модели. GPT и другие агенты используют те же `vmf.py tasks/reply`, `vmf_shot.py` и `hammer_shot.py`. Имена в коде/VMF не менять в рамках переноса инструкций.

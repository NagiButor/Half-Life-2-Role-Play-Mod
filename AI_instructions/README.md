# AI_instructions — единая база знаний HL2RPM

**Начать с [PROJECT.md](PROJECT.md), затем [CURRENT_STATUS.md](CURRENT_STATUS.md).** Это обычные Markdown-файлы для любой модели и любого AI-клиента с доступом к проекту.

## Содержимое

- `PROJECT.md` — что за проект, правила пользователя, пути, сборка и оглавление.
- `CURRENT_STATUS.md` — актуальная передача работы: где остановилась предыдущая сессия, что проверено и что открыто.
- `topics/` — 16 технических тем, перенесённых из `claude_docs`; детали реализации, команды, решения и ловушки.
- `skills/` — четыре пошаговые процедуры с рабочими скриптами: карты, playtest, RPG/диалоги, озвучка.
- `history/` — 31 исходный файл памяти предыдущего агента, включая `MEMORY.md`; датированные записи, не независимое подтверждение качества.
- `references/` — руководство CK и отчёты о подготовке Kimodo / MotionBricks.
- `archive/` — старые планы Trae, завершённый план CK, раннее исследование шейдеров, оригинал специализированного агента.
- `MIGRATION.md` — что перенесено, как устроена совместимость и какие данные сохранены.
- `migration-sources.json` — исходные пути и SHA-256 файлов до правок; путь полного резервного архива.
- `tools/setup_compat.ps1` — восстановление Windows-junction для совместимых путей после переноса/клонирования.

## Как это видят GPT, Claude и другие

**Автозагрузка зависит от приложения-агента, а не от семейства модели.** У модели должен быть доступ к папке и инструмент чтения файлов.

- В рабочей области и в git-корне есть `AGENTS.md`: вход для клиентов, которые поддерживают это соглашение (в том числе многих сред GPT).
- `CLAUDE.md` — короткий совместимый вход Claude Code к тем же файлам.
- `GEMINI.md` — такой же вход Gemini CLI.
- `.github/copilot-instructions.md` — вход для поддерживающих его сред GitHub Copilot.
- Файлы `skills/*/SKILL.md` читаются напрямую. Если клиент умеет Agent Skills, каталог `.agents/skills` и совместимые `.claude/skills` указывают на эти же процедуры; формат YAML `name`/`description` сохранён.
- В клиенте без автозагрузки достаточно первым сообщением дать текст ниже и подключить папку проекта.

```text
Работаем над HL2RPM. Сначала прочитай AGENTS.md, затем
AI_instructions/PROJECT.md и AI_instructions/CURRENT_STATUS.md.
По задаче открой нужный topics/*.md и skills/<имя>/SKILL.md.
Пользуйся общей памятью в AI_instructions и обнови статус после работы.
```

Обычный веб-чат без доступа к диску сам эти файлы не увидит: приложить папку/нужные файлы или подключить файловый доступ. Одного названия GPT/Claude недостаточно для автозагрузки.

## Одно хранилище, два удобных входа

Канонические файлы физически находятся в **`source-sdk-2013-mapbase-v8.0/sp/src/AI_instructions`**, внутри настоящего git-репозитория.
Папка **`HL2RPMSOURCE/AI_instructions`** — Windows-junction на это хранилище. Правка по любому из этих путей изменяет один файл.

В старых `sp/src/claude_docs` и `sp/src/hl2rpm_extras/claude_skills` оставлены короткие README-указатели. Установленные `.claude/skills/hl2rpm-*` и `.agents/skills` — локальные junction на канонические skills, без независимо редактируемых копий. Генераторы карт используют новый путь напрямую. В новых инструкциях используются пути `AI_instructions`.

Junction — локальные связи Windows, не переносимые git-ссылки. После клонирования каноническая база и `AGENTS.md` доступны сразу. Для восстановления старых путей выполнить из `sp/src`:

```powershell
powershell -ExecutionPolicy Bypass -File AI_instructions\tools\setup_compat.ps1
```

Если прежний путь после клонирования содержит файлы, скрипт оставит их и сообщит об этом: сначала сверить их с канонической базой. Основная инструкция и прямые пути `AI_instructions/skills` работают и без junction.

## Как обновлять

1. Правила и маршрутизация — `PROJECT.md`.
2. Детали конкретной системы — соответствующий файл в `topics`.
3. Повторяемая процедура — существующий `skills/<имя>/SKILL.md` и его скрипты.
4. Итог сессии — `CURRENT_STATUS.md`: дата, сделано, проверено каким способом, открытые вопросы.
5. Развёрнутый завершённый отчёт — новый датированный файл в `history`, с записью в его оглавлении.

Исторические записи не превращать в текущие инструкции. Различать «есть в исходниках», «собрано», «проверено в игре» и «принято пользователем».
